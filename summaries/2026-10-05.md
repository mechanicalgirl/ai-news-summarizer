### Pixel 11 doesn't yet meet the GrapheneOS security standards and may be skipped - (Hacker News)

https://discuss.grapheneos.org/d/41564-pixel-11-doesnt-yet-meet-the-grapheneos-security-standards-and-may-be-skipped

# Summary

GrapheneOS, a privacy-focused Android operating system, has announced it may skip supporting the Pixel 11 series because Google removed ARM hardware memory tagging (MTE) support—a critical security feature that GrapheneOS relies on across its entire OS to protect against remote and local exploits. While the Pixel 11 does include some security improvements like post-quantum verified boot and an upgraded Titan M3 chip, the loss of MTE represents a significant security regression compared to earlier Pixel models (8, 9, and 10), which all included MTE support.

The GrapheneOS team strongly recommends against purchasing Pixel 11 devices and is considering focusing development efforts on upcoming Motorola devices instead, which will include MTE. They plan to wait and see if the Pixel 11a includes MTE before deciding whether to support the Pixel 11 line at all. The decision reflects GrapheneOS's commitment to maintaining security standards rather than compromising on essential protection features.

### Web Search API - (Hacker News)

https://developers.cloudflare.com/changelog/post/2026-10-02-introducing-web-search-api/

# Summary

Cloudflare has launched Web Search API in beta, enabling AI agents and applications to search the internet in real-time and provide responses grounded in live information rather than relying on outdated training data. The API offers three search provider options—Ceramic.ai, Exa, and Linkup—all of which support zero data retention and comply with verified bot crawling standards.

Web Search API integrates with Cloudflare's AI Gateway, allowing search requests to be tracked in gateway logs and billed at standard provider API rates without additional markup. Developers can access the API through REST calls or directly from Cloudflare Workers using the AI binding, with the flexibility to bring their own provider API keys if preferred.

### Denmark Data Breach Exposes 8.8M People's Personal Data - (Hacker News)

https://www.cpr.dk/cpr-nyt/nyhedsarkiv/2026/okt/omfattende-uautoriseret-adgang-til-borgeres-cpr-oplysninger

# Summary

Denmark's Central Person Register (CPR) has disclosed a serious security breach in which unauthorized individuals exploited a legitimate Danish company's access to the system to obtain personal information on approximately 8.8 million Danish citizens. The compromised data includes names, addresses, and CPR numbers (national identification numbers), though individuals who had registered with name and address protection were not affected by the breach.

In response, the CPR administration has revoked the company's access and is investigating the incident in collaboration with specialists and authorities. The case has been reported to the Danish Data Protection Authority (Datatilsynet) and is under investigation by police and relevant government agencies.

### Making a GTK application in Haskell, part 1 - (Hacker News)

https://floreal.tech/blog/2026/making-a-gtk-app-in-haskell-part-1/

# Summary

This article introduces building a GTK 4 application in Haskell using the Adwaita library, which provides GNOME-compliant design components and styling. The tutorial demonstrates creating a todo-list application using the `haskell-gi` toolkit for Haskell bindings to GTK. It begins with a simple window example and then introduces the Elm Architecture (Model-View-Update pattern) as the organizational framework for the application's state management, user interactions, and side effects.

The article breaks down the todo app into three components: the Model (data structures for todos and application state), Messages (user interactions like adding tasks or changing status), and the Update function (which modifies the model and produces effects like saving). The View section then demonstrates how to construct the user interface using GTK widgets like Box, ListBox, EntryRow, and ActionRow, showing how these components connect together and dispatch messages back to the model when users interact with them. The article concludes by explaining that a Runtime section would tie together the Model-View-Update trio to create a fully functional application.

### Differences Between `Foldl` and `Foldr` - (Hacker News)

https://blog.haskell.org/foldl-and-foldr/

# Summary

The article explains that `foldl` and `foldr` differ not in traversal direction (both go left-to-right), but in **associativity**: `foldl` groups operations left-associatively `((a ⊗ b) ⊗ c)` while `foldr` groups them right-associatively `(a ⊗ (b ⊗ c))`. In strict languages, `foldl` is efficient (constant space, tail-recursive) while `foldr` requires linear space. However, in lazy languages like Haskell, this reverses: lazy `foldl` creates problematic nested thunks consuming linear space, making `foldl'` (the strict version) necessary for efficiency, while `foldr` becomes beneficial because it can leverage laziness to avoid evaluating unnecessary portions of the list when the reducing function is lazy in its second argument.

### Type Safe Generic Data Structures in C - (Hacker News)

https://danielchasehooper.com/posts/typechecked-generic-c-data-structures/

# Summary

Daniel Hooper presents a technique for creating type-safe generic data structures in C using unions and macros. He progressively builds up from simpler approaches—generic headers (which require multiple #includes), void pointers (not type-safe), and inline storage (more efficient memory layout)—to his final solution. The key innovation uses a union with a dummy "payload" member that exists only for compile-time type checking; when creating a list, the macro uses a ternary operator to ensure the item being added matches the list's payload type, allowing the compiler to catch type mismatches before runtime.

The approach works for any data structure (arrays, trees, maps, etc.) and avoids the downsides of template-style header inclusion while maintaining type safety and memory efficiency. The payload union member consumes no runtime memory and the technique leverages `__typeof__()` (now standard in C23) or the ternary operator for type enforcement. One caveat is that typedef declarations are needed when passing generic structures between functions, as the compiler treats separately-defined instances as distinct types.
