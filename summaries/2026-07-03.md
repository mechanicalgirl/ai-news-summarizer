### Shipping post-quantum cryptography to Python - (Python Weekly)

https://blog.trailofbits.com/2026/06/30/shipping-post-quantum-cryptography-to-python

# Summary

Trail of Bits has successfully implemented post-quantum cryptography support in pyca/cryptography, making it accessible to the entire Python ecosystem via a simple pip install. With funding from the Sovereign Tech Agency, they added ML-KEM (NIST-standard key establishment) and ML-DSA (NIST-standard digital signatures) to the library, which is critical given that the White House ordered federal systems to transition to post-quantum cryptography by 2030-2031. Since pyca/cryptography is the 11th most-downloaded package on PyPI with 1.2 billion monthly downloads, this implementation enables major Python projects like Ansible, Certbot, and Apache Airflow to begin their migration.

However, post-quantum primitives involve significant tradeoffs: public keys, signatures, and ciphertexts are 1-2 orders of magnitude larger than their classical counterparts (e.g., ML-DSA-65 signatures are 3,309 bytes vs. Ed25519's 64 bytes), requiring protocol redesigns beyond simple algorithm swaps. While ML-KEM and ML-DSA are now available in cryptography v48, future work includes implementing SLH-DSA and integrating these primitives into actual protocols and applications.

### Python: store extra data for objects in a WeakKeyDictionary - (Python Weekly)

https://adamj.eu/tech/2026/06/27/python-weak-key-dict-pattern/

# Summary

Adam Johnson describes a pattern for associating extra data with Python objects using `WeakKeyDictionary`. Rather than storing data as direct attributes on objects (which has drawbacks like incompatibility with built-in types, naming collisions, and unexpected visibility), this approach stores the data in a separate weak dictionary keyed by the object. The weak references ensure that when an object is no longer referenced elsewhere, its entry automatically gets cleaned up, preventing memory leaks while maintaining O(1) lookup performance.

The technique requires that objects be hashable and weak-referenceable—conditions usually met by user-defined classes, though some built-ins like `int` and `str` cannot be weak-referenced. Johnson also explains why `functools.cache` is insufficient for this use case, as it uses strong references that prevent garbage collection of cached objects.

### Why I wrote PEP 832 -- virtual environment discovery - (Python Weekly)

https://snarky.ca/why-i-wrote-pep-832-virtual-environment-discovery/

# Summary

The author, Brett Cannon, proposes PEP 832 to address a fundamental problem: tools like VS Code struggle to automatically discover which Python virtual environment to use for a given project. The challenge arises from the diversity of workflow tools (Hatch, Poetry, uv, etc.) and their varying environment storage locations—some keep environments locally in projects while others use global directories. Additionally, when first opening a project, there's no standard way for editors to know the developer's preferred workflow tool or which environment is intended for that project.

To solve this, Cannon proposes several mechanisms: treating `.venv` directories as the default discoverable location, creating a `.python-envs` file to list environment paths, and introducing a `[workflow]` table in `pyproject.toml` that specifies how to communicate with workflow tools via a standardized protocol. The goal is to make environment setup seamless and invisible to users across all experience levels while creating an editor-agnostic solution that benefits all development tools, not just VS Code.

### Free-threaded Python: past, present, and future - (Python Weekly)

https://lwn.net/Articles/1078367/

# Summary

Python's biggest recent development is the creation of a "free-threaded" version that removes the Global Interpreter Lock (GIL), enabling true parallel multithreading. Thomas Wouters, a CPython core developer at Meta, explained at PyCon US 2026 that the GIL was implemented decades ago to simplify thread support but now limits performance on modern multi-core systems. While alternatives like rewriting code in C/Rust, using multiple processes, or asyncio exist, they have significant drawbacks—removing the GIL would enable faster, more memory-efficient multithreaded solutions.

Efforts to remove the GIL date back to 1996, but previous attempts failed due to unacceptable performance losses in single-threaded code. Sam Gross at Meta finally developed a successful approach using techniques like thread ownership of objects, deferred reference counting, and speculative operations. This work, formalized in PEP 703, forms the basis of the current free-threaded Python implementation, which introduces some minor semantic changes (like delayed object reclamation) but achieves the long-sought goal of efficient parallel threading without sacrificing interpreter performance.

### Sparse Ranges - (Python Weekly)

https://paddy3118.blogspot.com/2026/06/sparse-ranges.html

# Summary

The article describes the development of `sparse_range`, a Python library that elegantly solves the problem of generating ranges with excluded values while maintaining memory efficiency. Unlike native Python ranges, which cannot efficiently handle "holes," `sparse_range` allows users to define permitted ranges (`s_in`) and forbidden ranges (`s_ex`), then generate filtered sequences that behave like standard Python ranges without storing values in memory.

The implementation uses a `RangePointer` system that dynamically aligns internal range cursors to match the traversal direction of the outer loop (forward or backward). A key technical challenge was reversing arithmetic progressions mathematically when the iteration direction changes, using formulas to recalculate start/stop boundaries rather than storing values. This architecture achieves O(1) to O(K) time complexity while maintaining zero memory overhead, making it both elegant and production-grade.

### How we used DSPy to turn AI evaluations into better responses in Dash chat - (Python Weekly)

https://dropbox.tech/machine-learning/how-we-turned-ai-evaluations-into-better-responses-in-dash-chat

# Summary

Dropbox used DSPy, an open-source framework for optimizing AI systems, to improve both their Dash chat agent evaluations and the agent itself. They created a comprehensive evaluation system with LLM judges that assess multiple dimensions of agent performance—including intent understanding, tool use, context selection, and task completion—rather than just final response quality. The judges were calibrated against human-labeled examples using detailed rubrics and structured failure codes to ensure their scores aligned with human judgment.

The result was significantly fewer incomplete answers and reduced token usage without compromising answer quality.
