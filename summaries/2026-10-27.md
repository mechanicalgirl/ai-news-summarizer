### Uber Moves Beyond CPU Cores with Performance-Aware Scheduling for Stateful Workloads - (InfoQ)

https://www.infoq.com/news/2026/10/uber-cpu-stateful-workloads/

# Summary

Uber has introduced Normalized Compute Units (NCUs) within its Odin orchestration platform to address performance inconsistencies across its heterogeneous server fleet of approximately 5 million CPU cores. Since single-threaded performance can vary by nearly 2x between the fastest and slowest processors, traditional CPU core allocation creates inefficiencies—either wasting capacity on faster machines or under-provisioning workloads on slower hardware. NCUs decouple compute performance requirements from physical cores by assigning each server type a performance factor (baseline 100, with newer hardware reaching ~190), allowing Odin to allocate different numbers of physical cores while maintaining comparable computational capacity.

This approach is particularly critical for stateful workloads, which cannot be easily load-balanced across machines like stateless services. Uber has rolled out performance-aware scheduling across 1.4 million CPU cores, achieving significant improvements: CPU utilization variance between server types dropped from 8 percentage points to 3, and total Kafka CPU allocation decreased by approximately 8%. The system continuously refines performance factors using production measurements rather than synthetic benchmarks, accounting for technology-specific variations (ARM vs. x86, older vs. newer hardware).

### How Anthropic Redesigned Source Control for AI-Driven Development - (InfoQ)

https://www.infoq.com/news/2026/10/anthropic-source-control/

# Summary

Anthropic has migrated its monorepo from Git to Scion, a custom source control system designed for AI-driven development at scale. Scion moves repository operations to the server side, using content-addressed storage and tiered caches to handle Anthropic's explosive growth—from 2,500 daily merged changes in May to over 30,000 by September, with 25 million daily CI checkouts against a 100 GB monorepo. The system sacrifices offline independence for reduced local data requirements and shared infrastructure benefits.

Scion's architecture records changesets with file-level changes and uses server-side "derived data" structures for history and blame queries, allowing evolution without client updates. Its tiered caching system (local daemon → regional caches → authoritative servers) achieves 99%+ cache-hit rates and delivers two orders of magnitude faster checkouts for CI jobs while reducing infrastructure footprint by 200x. However, Anthropic cautions that Scion is not a general Git replacement—it requires custom code-review and CI systems—and recommends other organizations adopt selected ideas like comprehensive server-side APIs rather than wholesale replacement.

The presentation introduces concepts like KV cache management, tiered storage, and tail latency reduction as key optimization techniques.

### AWS Shows Use of AI Agents to Triage Linux Kernel CVEs - (InfoQ)

https://www.infoq.com/news/2026/10/aws-ai-agents-linux-kernel-cves/

# Summary

AWS engineers presented their approach to managing the explosive growth in Linux kernel CVEs, describing a three-stage triage process combining automated filtering, AI agents, and human review. After the Linux kernel became a CVE Numbering Authority in 2024, CVE volume increased dramatically from 2 per week to 16 per day. An automated script first removes approximately 70% of CVEs by checking version ranges and configuration compatibility, while an AI agent classifies the remaining CVEs by affected subsystem, vulnerability type, and attack vector in about 3.4 seconds per CVE—far faster than manual review.

The team emphasizes that human engineers still review all AI classifications, as they "don't want to hinge our entire security posture on the output of an LLM agent," with the AI agent estimated to make problematic decisions 5-10% of the time. AWS also advocates for moving to newer long-term-support (LTS) kernels, as their data shows older branches accumulate significantly more unfixed CVEs and receive backported fixes more slowly, making kernel maintenance more efficient and secure overall.

### Cloudflare and VoidZero Introduce tsrs: An AI-Generated Rust Port of TypeScript - (InfoQ)

https://www.infoq.com/news/2026/10/cloudflare-tsrs-ai-typescript/

# Summary

Cloudflare and VoidZero have introduced tsrs, an AI-generated Rust port of the TypeScript compiler that achieves up to 8x faster type checking and 70% less memory usage compared to TypeScript 7.0. The project was created by directing Claude Opus 5.5 AI agents to produce a faithful port using TypeScript's 15,197 conformance cases as specifications, rather than manual coding. The tool can be used as a drop-in replacement and also compiles to WebAssembly, enabling type checks to run in browsers or on Cloudflare Workers.

While tsrs remains experimental and lacks some features like watch mode and language server support, it demonstrates the practical potential of AI-assisted code generation and has prompted optimization improvements in TypeScript itself. Cloudflare is merging tsrs with the rival Rust port tsc-rs into a single package, positioning it alongside Microsoft's Go-based tsgo compiler. Real-world testing shows performance gains ranging from 2.7x to 5.3x depending on the baseline TypeScript version used for comparison.

### Developers Reporting Double-Digit Weekly Time Savings From AI Fell From 68% to 26% - (InfoQ)

https://www.infoq.com/news/2026/10/atlassian-devex-2026/

# Summary

According to Atlassian's 2026 State of Developer Experience report, the percentage of developers reporting double-digit weekly time savings from AI tools dropped dramatically from 68% to 26% in a single year, despite near-universal AI adoption (95% of developers). While 87% of developers still report that AI helps them ship faster, the perceived friction has shifted rather than diminished—only 28% report noticeably less friction than before AI, with 50% experiencing similar friction of a different type.

The decline in time savings appears driven by new management overhead: 49% of developers now spend four or more hours weekly managing AI tools, and 65% spend time correcting AI-generated work. A key finding reveals a "metric problem" rather than a tooling problem—60% of developers say AI usage is treated as a productivity signal, leading some to use AI more than necessary. Organizations with clear, actively implemented AI strategies fare better, with 41% of those developers reporting less friction versus only 22% at organizations with inconsistent strategies.

### OpenTofu 1.13 Lets Module Authors Reduce Unknown Values at Plan Time - (InfoQ)

https://www.infoq.com/news/2026/10/opentofu-1-13-unknown-values/

# Summary

OpenTofu 1.13 introduces new functions that enable module authors to resolve more expressions during the planning phase, reducing unknown values that would otherwise block execution. The key additions include a `convert` function that specifies types for values (such as YAML decoded outputs) and `assumenotnull` to handle conditional resources, allowing the planner to determine resource counts without knowing all final attributes. These features address a limitation identified by maintainer Martin Atkins, matching similar functionality already available in Terraform 1.15.

The release also includes experimental features such as built-in linting with rules for unused variables and alternative count patterns, and Symbol Libraries for sharing functions and type definitions. Additionally, OpenTofu 1.13 removes WinRM support, updates macOS requirements to version 13+, and addresses two security vulnerabilities related to CPU usage during initialization and certificate handling. The version is supported until August 1, 2027.

### Readyon Builds Four Layer Tenant Isolation for Multi Tenant Amazon EKS - (InfoQ)

https://www.infoq.com/news/2026/10/readyon-four-layer-isolation/

# Summary

ReadyOn has implemented a comprehensive four-layer tenant isolation architecture for its Harmony workforce intelligence platform on Amazon EKS to securely serve multiple enterprise customers processing sensitive payroll and organizational data. The design combines Kubernetes namespaces with RBAC and network policies (layer 1), dedicated Karpenter node pools with dual taints (layer 2), VPC security groups and private API endpoints (layer 3), and separate Aurora database clusters with tenant-scoped credentials (layer 4). This multi-layered approach addresses a fundamentally different threat model than single-tenant clusters, particularly preventing lateral movement from compromised tenant workloads.

The architecture has generated broader industry discussion about multi-tenant Kubernetes security best practices. Industry experts emphasize that while Kubernetes namespaces provide logical isolation, stronger separation requires additional controls like node affinity and taints. Notably, security experts also stress that isolation controls must be paired with corresponding observability—connecting workload identity with database and network enforcement—to avoid false confidence in security posture.

### Article: The Evolution of Agentic Harnesses: From Chains to Graph to Code - (InfoQ)

https://www.infoq.com/articles/agentic-ai-architecture-harness-evolution/

# Summary

Agentic LLM systems have evolved through three distinct paradigms: **Chains**, **Graphs**, and **Code harnesses**. Chains represent simple linear workflows where LLM outputs feed sequentially into the next step, offering low latency and compute costs but remaining fragile—a single failure can cascade throughout execution. Graphs introduce explicit structural control through nodes and edges, enabling conditional branching, parallelism, and state management for improved resilience in complex multi-step tasks.

Code harnesses represent the most advanced approach, treating execution as a first-class primitive within sandboxed environments to deliver deterministic, verifiable outputs with the strongest reliability guarantees. The article emphasizes that developers should treat LLM outputs as untrusted input, decouple planning from execution, invest in observability, and select the least complex design that meets their reliability, speed, and cost requirements—reflecting the industry's maturation from ad-hoc prompt experiments toward production-grade agentic AI architectures.

### Cloudflare’s Auto Router Rates Each Request for Stakes, from the Most Recent Turns - (InfoQ)

https://www.infoq.com/news/2026/10/cloudflare-auto-router/

# Summary

Cloudflare has released Auto Router in public beta through AI Gateway, a system that dynamically selects the best AI model for each request. The router operates in two stages: first filtering candidate models based on request format, credentials, and constraints, then using a multi-head classifier to rate requests across four dimensions (complexity, ambiguity, stakes, and context dependence) and score models based on expected quality minus adaptive cost penalties.

The key innovation is balancing cost and quality—Cloudflare's benchmarks show that using cheaper models can save roughly one-third on spending while sacrificing only ten points of reliability, allowing teams to choose their preferred trade-off. However, practitioners have raised concerns about the system's limitations, particularly that it classifies requests based only on recent conversation turns (capped at 8 KiB), which could underestimate risk in long agent sessions where critical context appears early. The routing decisions are auditable through response headers, though some documentation inconsistencies and potential drift in the default model pool warrant verification before fully trusting the published benchmarks.

### MCP C# SDK 2.0 Makes HTTP Stateless by Default and Adds Multi Round-Trip Requests - (InfoQ)

https://www.infoq.com/news/2026/10/MCP-CSharp-SDK-Stateless/

# Summary

Microsoft released MCP C# SDK 2.0, a major update implementing the Model Context Protocol specification that fundamentally redesigns HTTP communication. The key innovation is making HTTP servers stateless by default, eliminating the need for sticky routing or shared session stores—protocol version and capabilities now travel with every request. The update also introduces standardized HTTP headers (Mcp-Method, Mcp-Name, Mcp-Param-*) to enable infrastructure-level routing without reading request bodies, and replaces server-initiated input requests with Multi Round-Trip Requests (MRTR) for interactive tools.

The release maintains backward compatibility with stable 1.x APIs (except for the Tasks package, which moved to an optional extension). Additional improvements include stricter OAuth validation with RFC 9207 issuer validation, mandatory PKCE S256 support, and support for .NET 8, 9, and 10. Three minor follow-up versions (2.1-2.3) added subscriptions for custom notification streams, improved multi-version client support, and made ServerInfo nullable to handle optional identity metadata safely.

### Are agent harnesses dying? What harness distillation changes. - (Radar)

https://www.oreilly.com/radar/are-agent-harnesses-dying-what-harness-distillation-changes/

# Summary

The article discusses how "harness distillation"—a technique that trains a model to internalize behaviors previously handled by agent harnesses—is changing the role of harnesses rather than eliminating them entirely. Research from Peking University's "Harness-Zero" project demonstrated that specialized harness logic can be distilled into a model through fine-tuning with corrected training data, resulting in better performance than the original model-plus-harness combination.

However, harnesses aren't disappearing; instead, their purpose is evolving. The generalizable components of harnesses can now be trained directly into models, leaving harnesses to handle only the unique elements specific to each application: custom tools, data, users, and environment. This means developers must be prepared to regularly rebuild and update harnesses as models evolve, transforming what could be a time-consuming manual process into an automated workflow.

### Soloists, Copy-Pasters, and Tourists - (Radar)

https://www.oreilly.com/radar/soloists-copy-pasters-and-tourists/

# Summary

This O'Reilly article examines how different team members adopt and use AI tools like GitHub Copilot, revealing that adoption timing (measured by Rogers's diffusion curve) doesn't predict actual usage patterns or outcomes. The author identifies five distinct user types—from engineers generating 40 pull requests daily to those who abandoned the tool—and notes that even "early adopters" achieve vastly different results and create different risks for their teams.

The article argues that AI has shifted the development bottleneck from code writing to code review and system comprehension. Rather than responding to this by moving faster and breaking things (as past tech shifts encouraged), teams need structure: clear roadmaps, problem statements before solutions, and design reviews focused on trade-offs. This framework enables safe speed, much like how jazz musicians can improvise freely only because they share understanding of chord changes and musical form.

### Owners, Not Renters: Raffi Krikorian on Open Source AI - (Radar)

https://www.oreilly.com/radar/owners-not-renters-raffi-krikorian-on-open-source-ai/

# Summary

Raffi Krikorian, Mozilla's CTO, advocates for an open-source AI ecosystem that empowers individuals rather than concentrating power in the hands of large AI companies. He envisions a future where billions of people have personal AI agents they can trust to act in their interests, rather than seven centralized AGIs optimized for corporate profit. Drawing parallels to how Firefox helped preserve an open web against Microsoft's dominance, Krikorian argues that open-source AI is essential to prevent similar corporate control in the AI age.

Beyond open-source models alone, Krikorian outlines the infrastructure needed to build trustworthy personal AI agents: memory systems for private data, tool-calling capabilities for real-world actions, runtime environments, and proper governance frameworks. Mozilla aims to establish open standards and protocols in these areas, allowing developers to innovate freely and build AI systems tailored to user needs rather than replicating proprietary corporate solutions. This approach reflects the core open-source principle of solving problems through community-driven innovation without requiring permission from centralized gatekeepers.
