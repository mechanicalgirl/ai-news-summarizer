### Jitter is the cheapest reliability fix you are not using - (Python Weekly)

https://ankit-rana.com/logs/49-jitter-synchronised-clients/

# Summary

**Jitter** is a simple but overlooked reliability technique where randomness is added to fixed intervals in distributed systems to prevent synchronized load spikes. Without jitter, independent processes naturally align over time due to shared events like deploys, network partitions, or cache flushes, causing all clients to retry, reconnect, or refresh at exactly the same moment. This creates a "thundering herd" problem that can prevent failing services from recovering.

The article demonstrates how jitter is a one-line fix that spreads concentrated load across time without changing average rates or requiring coordination. Common overlooked culprits include retry logic, cron jobs, health checks, token refresh, and reconnect delays. While jitter has limitations (it doesn't prevent unbounded retries or fix cold starts), the author recommends making jitter the default in scheduling and retry helpers so it's applied automatically across systems, transforming dangerous load spikes into manageable, distributed load patterns at virtually zero cost.

### There are only twelve 4x4 sudokus - and a cool trick for finding minimal subsets - (Python Weekly)

https://baldino.dev/blog/there-are-only-twelve-4x4-sudokus/

# Summary

The article explores how many unique 4x4 sudoku solutions exist, finding that while there are **288 total solutions**, there are only **12 structurally distinct solutions**. The distinction arises because the digits 1-4 are arbitrary symbols; permuting them produces different solutions with identical underlying structures. The author demonstrates this by showing that every unique structure can be represented by a solution starting with "1 2 3 4" in the first row, creating a one-to-one correspondence between distinct structures and solutions with that constraint.

The author uses a brute-force depth-first search algorithm in Python to enumerate all solutions, then refines the approach to count only those starting with "1 2 3 4" in the first row. This clever mathematical trick elegantly reduces the problem from 288 to 12, confirming theoretical predictions that dividing 288 by the 24 possible digit permutations (4!) yields exactly 12 distinct sudoku structures.

### The last mile of a long road: faster NumPy in the browser - (Python Weekly)

https://notebook.link/blog/the-last-mile-faster-numpy/

# Summary

NumPy in the browser has achieved a major performance breakthrough through the integration of OpenBLAS in WebAssembly. Previously, NumPy operations in the browser relied on unaccelerated portable C loops, resulting in poor performance. Now, with OpenBLAS 0.3.34 linked via Emscripten-forge, matrix multiplication performance has improved dramatically—approximately 30.92× faster for float32 and 14.90× faster for float64 at standard matrix sizes.

This achievement required significant infrastructure work, including developing a Fortran compiler (Flang) for WebAssembly to support BLAS and LAPACK libraries, and adapting OpenBLAS to work with WebAssembly's stricter calling conventions. The upcoming OpenBLAS 0.3.35 release (with contributions from QuantStack) will push performance even further through optimized SIMD kernels, with additional gains available through WebAssembly Relaxed SIMD on supported engines. The Emscripten-forge packaging model enables this progress by treating BLAS as a separate, upgradeable package that benefits the entire scientific Python ecosystem in the browser.

### Soft-deprecating re.match() - (Python Weekly)

https://hugovk.dev/blog/2026/soft-deprecating-re.match/

# Summary

Python 3.15 introduces `re.prefixmatch()` as a replacement for the confusing `re.match()` function, which only matches at the beginning of a string rather than anywhere within it. The article explains the differences between three regex matching functions: `re.match()` anchors only at the start, `re.search()` matches anywhere in the string, and `re.fullmatch()` anchors both start and end. Because `re.match()`'s "half-anchored" behavior is counterintuitive and has confused users for decades, it has been soft-deprecated in favor of the more explicit `re.prefixmatch()`.

A soft deprecation is a documentation-level recommendation that discourages new code from using an API while maintaining full support for existing code—it doesn't issue warnings or guarantee future removal. The article provides a comparison table of all three functions and recommends using linting tools like Ruff to automatically flag `re.match()` usage in codebases.

# Summary

Armin Ronacher discusses the debate around AI safety and "pacing" (slowing AI development), while sharing his concerns that the real problem isn't existential doom but rather how closed-weight AI models controlled by a few American corporations (OpenAI and Anthropic) are causing immediate harm through cyberattacks, data exploitation, and economic distortion. He argues that the proposed solution—having a few companies and evaluators control AI development—is problematic given these companies benefited from public data and now wield geopolitical power.

Ronacher contends that open-weight models would actually provide "automatic pacing" through natural proliferation and competition, preventing monopolistic control and the distorted economics that enable abuse. He criticizes the regulatory failure that allows companies to ignore existing laws regarding data use and argues that ideally, regulations would have forced labs to support the commons they benefited from. Rather than fearing AI extinction events, he worries about immediate, widespread damage: persistent cyberattacks, massive costs for institutions forced to use proprietary models, and the creation of a exploitative "token economy" reminiscent of drug markets.
