### Making np.searchsorted up to 25× Faster in NumPy 2.5 - (Python Weekly)

https://blog.scientific-python.org/numpy/searchsorted/

# Summary

NumPy 2.5 achieves up to 25× speedup in the `np.searchsorted` function by vectorizing the binary search algorithm. Rather than performing sequential binary searches for each key independently (as in NumPy 2.4), the optimized approach represents the search state for all queries as arrays and updates them simultaneously using vectorized operations. This allows the CPU to process multiple independent searches in parallel, reducing Python overhead and enabling efficient batching of operations in compiled C++ code.

The key insight is that all binary searches can be made to take the same fixed number of iterations (log₂ n) without requiring an "active mask" to track which searches have completed, making the algorithm simpler and faster. Additionally, the state can be reformulated to use less memory by tracking interval boundaries instead of separate lo/hi values for each query. This vectorized approach overcomes the cache-unfriendliness of sequential binary search by keeping multiple memory accesses in flight simultaneously, particularly benefiting performance when array sizes exceed CPU cache limits.

### TurboPython - (Python Weekly)

https://tpy-lang.org/

# TurboPython Summary

TurboPython is a statically-typed Python-to-C++ compiler that enables developers to write Python-like code while achieving native binary performance with memory safety guarantees. It combines familiar Python syntax with an ownership model (similar to Rust) that eliminates garbage collection, automatic reference counting, and the Global Interpreter Lock, providing predictable performance and compile-time memory safety. The language can be installed as a simple Python package and compiles to standalone binaries or CPython extensions.

The key trade-off is that TurboPython requires explicit type annotations and an ownership model where each value has exactly one owner, differing significantly from Python's dynamic reference counting. Developers lose access to pip packages and Python's dynamic features, instead working with a subset of the standard library, but gain performance, memory efficiency, and compile-time error detection for use-after-free and aliasing bugs. The language is currently in early development, with some ordinary Python constructs still rejected and known bugs possible.

### Making a mathematical model for better Indic keyboards - (Python Weekly)

https://triangulatedexistence.mataroa.blog/blog/making-a-mathematical-model-for-better-indic-keyboards/

# Summary

This article describes a mathematical model for creating improved Indic language keyboards based on the phonological structure of these languages. The author uses the Tamil script as a case study, organizing consonants into a grid based on place and manner of articulation (Vallinam, Mellinam, Idaiyinam, and Sibilants), then applies Boolean algebra and truth tables to map user inputs to valid characters. The approach involves four main steps: organizing linguistic data into tables, creating coarse validity truth tables for rows, generating fine position truth tables for columns, and deriving simplified Boolean expressions using computer algebra systems to determine valid vs. invalid input combinations.

The result is a systematic framework that can be generalized to other Indic scripts, allowing keyboards to enforce linguistic rules automatically. By mapping phonological features to binary logic circuits, the author creates an input system where users select features (aspiration, voicing, nasality) and the keyboard restricts available options to only valid character combinations—similar to how a 12-key phone keyboard works for multiple languages. The working prototype is available online, with implementations in Python (for the mathematical derivations) and TypeScript (for the interactive keyboard interface).

### First Steps into Memory Management in Python - (Python Weekly)

https://tech.daniellbastos.com.br/posts/python-memory-management/

# Summary

Python uses two memory allocation strategies: pymalloc for small objects (≤512 bytes) and malloc for larger ones. Pymalloc organizes memory into arenas, pools, and blocks for efficient reuse, but this means Python processes rarely shrink in size—a single live object can prevent an entire arena from returning to the OS. Memory deallocation occurs through reference counting, which immediately frees objects when their reference count reaches zero, and a garbage collector that handles circular references by periodically scanning for unreachable objects across multiple generations.

The author emphasizes that while programmers cannot fully control when memory returns to the OS (that's decided by the allocator), they can optimize memory usage by managing reference lifetimes—for example, by deleting large objects after use or passing them directly to function calls rather than storing them in variables. Understanding these internals reveals that Python memory management is more complex than it initially appears, with connections to OS-level allocation and interpreter execution.

### Why Pendulum had to write the most cursed + operator in all of Python - (Python Weekly)

https://dev.arie.bovenberg.net/blog/pendulum-cursed-plus-operator/

# Summary

Pendulum, a popular Python datetime library, implements an unusually problematic `+` operator that inspects the call stack to decide which arithmetic behavior to apply. This hack exists because Pendulum made two conflicting promises: providing DST-aware arithmetic (different from the standard library) while also being a drop-in replacement for the standard library's datetime class. When the standard library's `astimezone()` method internally uses `+` during timezone conversion, Pendulum's overloaded operator produces incorrect results, so it checks if the caller is `astimezone()` to determine which behavior to use. This approach is fragile, unreliable on different Python implementations, and makes the `+` operator 600 times slower than the standard library's.

The author argues that Pendulum didn't actually need this hack—a cleaner solution exists: converting to a plain datetime before calling the standard library, then wrapping the result back. This approach (which Pendulum has now merged) eliminates the guessing and makes `+` only 120 times slower. However, the fundamental issue remains: Pendulum cannot be both a true drop-in replacement and have different arithmetic semantics. Users should either stick with the standard library datetime or switch to libraries like `whenever` that don't attempt to be drop-in replacements and avoid silent guessing altogether.

### What is Codemode - (Armin Ronacher's Thoughts and Writings)

https://lucumr.pocoo.org/2026/10/6/codemode/

# Summary

Armin Ronacher explains Codemode, a feature in Pi 1.0 that allows LLMs to orchestrate complex operations on the harness (brain) side rather than just the execution environment. Unlike traditional tool calls that are limited by context windows and bash composability, Codemode runs JavaScript in a sandboxed environment (QuickJS/WASM) with controlled access, enabling the agent to handle larger outputs, maintain state across sessions, and access internal model APIs like image generation and text classification without wasting context tokens.

The article demonstrates Codemode's practical advantages through real examples: agents can generate images directly through model APIs, perform batch sentiment analysis on GitHub issues using classifier models, and even drive game engines for debugging—all while managing concurrent operations and storing intermediate results. This approach addresses fundamental limitations of bash-based tools while maintaining security through the separation between the trusted harness and the sandboxed execution environment.
