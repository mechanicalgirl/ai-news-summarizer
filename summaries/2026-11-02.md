### Moving our warehouse off DuckDB - (Hacker News)

https://posthog.com/blog/moving-off-duckdb

# Summary

PostHog is migrating its data warehouse from DuckDB to Trino with their custom HogLake format after discovering that DuckDB's single-node architecture couldn't efficiently handle their customers' complex, large-scale workloads. While DuckDB excels as a local analysis tool, scaling it in the cloud required massive instances and made resource prediction difficult. Additionally, DuckLake (the lakehouse extension) suffered from performance issues at PostHog's petabyte scale, particularly with metadata management and catalog writes that took several minutes.

Beyond technical limitations, PostHog found that offering direct Postgres connections over port 5432 proved harder to scale than HTTP and created compatibility challenges across different Postgres clients. The company decided a purpose-built distributed warehouse architecture was necessary to deliver the performance, scalability, and cost-efficiency their customers expect, leading them to rebuild on Trino with their own open table format, HogLake.

### If you love a website, back it up - (Hacker News)

https://blog.mistys-internet.website/post/2026/10/29/if-you-love-a-website-back-it-up/

# Summary

A web archiving professional shares the story of losing access to a beloved fansite (teapuppies.com) when its domain was repurposed for gambling ads, prompting her to advocate for personal web archiving. She emphasizes that ordinary people can—and should—preserve websites they care about using accessible tools, rather than relying solely on organizations like the Internet Archive.

The article provides practical guidance on three archiving methods: the ArchiveWeb.page browser extension (easiest for single pages), a standalone app version, and Browsertrix (best for archiving entire websites automatically). It also explains how to view and share archived sites through various formats, stressing that keeping multiple copies of archives in WACZ files ensures long-term preservation of important digital content.

### We halved DNS build delay and cut memory use by 85% - (Hacker News)

https://blog.cloudflare.com/dns-targeted-zone-builds/

# Summary

Cloudflare optimized its DNS propagation pipeline to handle exponential growth in DNS record volumes and zone sizes. The company reduced DNS build delays by 50% and cut memory usage by 85% while managing a threefold increase in events (from 250 to 700 DNS changes per second) and zones containing up to 20 million records. The core challenge was that build times—the process of converting DNS changes into data usable by authoritative servers—grew with zone size, particularly for large zones expected to eventually reach hundreds of millions of records.

The optimization involved improving how the Zone Builder processes events and converts database state into edge-compatible formats, significantly enhancing performance and resource efficiency to support continued scaling of their DNS infrastructure.

### Show HN: I've updated my Linux System Call website and API - (Hacker News)

https://syscall.sh/

# Summary

**syscall.sh** is a comprehensive online reference that catalogs Linux system calls across 27 different processor architectures, including x64, ARM, RISC-V, PowerPC, and others. The site provides detailed information for each syscall including its number, arguments, registers, and calling conventions, covering Linux kernel versions from 3.3 to 7.3. Each architecture's data is available both as an interactive table and as JSON files for programmatic access.

The resource tracks the complete history of syscalls, documenting when each call was introduced and, rarely, when it was removed from specific architectures. The data is generated directly from the Linux kernel source code itself, ensuring accuracy, and includes calling convention details showing exactly which registers and instructions are used for system call invocation on each architecture.

### WTF Ubuntu? - (Hacker News)

https://chalmovsky.com/posts/wtf-ubuntu

# Summary

This article criticizes Ubuntu's slow response to CVE-2026-98432, a critical Linux kernel vulnerability (CVSS 9.8) that has existed since 2016 and allows remote root access on virtually all Linux servers. While Debian patched it on October 16 and volunteer-run distros like Arch and Alpine followed suit, Ubuntu—despite marketing itself with promises of "timely patches for critical vulnerabilities"—had not released a patch more than two weeks later as of the article's date, leaving all supported releases vulnerable.

The author expresses deep frustration with Ubuntu's broken promises, arguing that corporate marketing language like "enterprise-grade" and "production-grade" has become meaningless. Particularly galling is that Ubuntu, a commercial company selling security subscriptions, was outpaced by volunteer-run distributions. The author has lost trust in Ubuntu and decided to migrate all servers away from it, even taking some offline until they could complete the migration.
