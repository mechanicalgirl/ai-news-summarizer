### Caching at Scale in Django: Lessons from Production - (Python Weekly)

https://johnnymetz.com/posts/caching-at-scale-in-django/

# Summary

This article outlines how Johnny Metz's team scaled a Django API to handle 20x traffic growth through strategic caching with Redis. Rather than traditional scaling (larger database, read replicas), they identified high-volume queries as the bottleneck and implemented a two-tier caching strategy: storing expensive permission checks per-user while sharing serialized document bases globally. This approach dramatically reduced invalidation overhead—from clearing thousands of user-specific keys to just one shared key per write.

The team also adopted best practices including long TTLs (7 days) with precise, immediate invalidation via Django signals; flat data structures to minimize invalidation cascades; and careful monitoring to handle Redis failures gracefully. Results were dramatic: during rollout, latency dropped 40% while database queries per request fell from multiple to 0.3, with Redis achieving 97% cache hit rates and absorbing all subsequent traffic growth.

### The State of Python Profiling in 2026 - (Python Weekly)

https://p403n1x87.github.io/the-state-of-python-profiling-in-2026.html

# Summary

As of 2026, Python profiling has undergone significant changes with CPython 3.15 now shipping its own sampling profiler called Tachyon, while free-threaded builds have become mainstream and AI coding agents increasingly analyze profiles. This article provides a comprehensive comparison of four major sampling profilers—Tachyon, py-spy, Scalene, and Austin—examining their design choices (in-process vs. out-of-process), strengths, and use cases.

The article emphasizes that sampling profilers have become the preferred approach over traditional tracing profilers due to their superior accuracy and minimal overhead (0-2% vs. 73%+ for tracing tools). The landscape has evolved from external tools like Austin reverse-engineering CPython's internals to the interpreter now officially supporting out-of-process profiling through features like the debug offsets table and remote debugging support. Raw sampling speed has become increasingly important for accuracy, with modern profilers like Austin 4.1 achieving 10,000 samples per second, directly influencing which tool best suits different profiling needs.

### Unnecessary syntax in Python - (Python Weekly)

https://www.pythonmorsels.com/unnecessary-syntax/

# Summary

This article argues that some "unnecessary" syntax in Python can actually improve code readability and should be retained. Examples include explicitly returning `None` rather than relying on implicit returns, using `else` statements to show equal significance between code branches, specifying keyword arguments like `start=` in `enumerate()`, and adding trailing commas to lists. The author emphasizes that Python code must be readable by humans, not just interpreters.

The key principle is that syntax shouldn't be removed simply because it's technically redundant—if it clarifies intent and improves understanding, it should stay. The article covers various cases (parentheses, whitespace, named variables, string concatenation) where explicit, seemingly unnecessary syntax often makes code more maintainable and easier to understand, aligning with Python's philosophy that "explicit is better than implicit."

### pyinfra – simple infrastructure automation in Python - (Python Weekly)

https://death.andgravity.com/pyinfra

# Summary

**pyinfra** is a Python-based infrastructure automation tool that converts Python code into shell commands and executes them on multiple servers via SSH. Unlike Ansible, which uses YAML, pyinfra allows you to write deploys in Python, enabling features like loops, conditionals, code completion, and library imports while remaining declarative and idempotent. The tool is faster than Ansible and easier to learn, making it ideal for configuring servers, managing self-hosted infrastructure, and running ad-hoc commands across server fleets.

The article demonstrates pyinfra through a practical example of deploying two websites (a landing page and Python web app) across local and production environments. It introduces key concepts like **operations** (which change server state) and **facts** (which gather host information), showing how operations work by reading host state via facts, comparing it to desired state, and generating only the necessary commands to reach that state—ensuring idempotency and reproducibility.

### Migrating to Python 3.15 - (Python Weekly)

https://mathspp.com/blog/migrating-to-python-315

# Summary

This article provides a migration guide for Python 3.15, organizing new features into three categories: backwards-compatible features you can use immediately, backwards-incompatible features requiring 3.15+ support, and 3.11 features now universally supported. Key backwards-compatible additions include lazy imports, typing improvements via `typing_extensions`, the new Tachyon profiler, and `abi3t` for C extensions. Major backwards-incompatible features include built-in `frozendict`, `sentinel`, full lazy imports, thread-safe iterators, and unpacking in comprehensions.

The guide recommends adopting backwards-compatible features now, using lazy imports for faster startup times, defaulting to `frozendict` for immutability and thread safety, and leveraging features like exception groups and `tomllib` from Python 3.11 that are now universally available. The author advises developers to assess their projects' constraints and begin using appropriate new features either by upgrading to 3.15+ or by increasing the minimum supported version to 3.11/3.13 to access newly universal features.
