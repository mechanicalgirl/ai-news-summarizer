https://gruhn.me/blog/2026-08-03/

# Summary

The author argues against simply copying and pasting AI-generated responses directly to others without adding value. The effort to genuinely comprehend and synthesize AI output is the real value a human can contribute.

### Rust project goals: Immobile types and guaranteed destructors - (Hacker News)

https://github.com/rust-lang/rust-project-goals/blob/main/src/2026/move-trait.md

# Summary

The Rust project proposes introducing new traits—**Move**, **Destruct**, and **Forget**—that allow types to opt out of traditionally universal capabilities. Currently, Rust assumes all types can be moved in memory and forgotten via `mem::forget`, but some types need to violate these assumptions. The **Move trait** would encode immovability as a type property (simpler than the current `Pin` approach), while the **Forget trait** would enable guaranteed destructors, allowing patterns like safe scoped spawn for async code. This work applies the same principle as the Sized hierarchy work, relaxing blanket assumptions through opt-out trait hierarchies.

The initiative spans 2026-2027 and includes compiler implementation, RFC writing, and real-world testing in the Linux Kernel. Key work items include implementing the Move trait, exploring guaranteed destructors, and validating compatibility with iterators and generators. The proposal is intentionally an alternative to pin ergonomics efforts, aiming to eventually deprecate Pin entirely rather than extending its complexity.

### AI migrated legacy COBOL programs to Java, bugs included - (Hacker News)

https://arxiv.org/abs/2607.28271

# Summary

This paper presents the "Locksmith Loop," a novel agentic method for validating COBOL-to-Java code migrations. The approach instruments both the original COBOL and generated Java code with mocks in commodity hardware environments, then uses an iterative AI-driven loop to search for test inputs that penetrate different program branches. When exploration plateaus are reached, the system identifies "Locked Paragraphs"—conditions blocking deeper code exploration—and applies parity-preserving mutations to overcome them.

Tested on three case studies (two open-source and one production-like COBOL program ranging from 430-4,114 lines), Locksmith achieved near-complete branch coverage on open-source programs and 91.90% coverage on the production program. Critically, the method validates generated Java code against the COBOL reference using deterministic parity checks, providing—to the authors' knowledge—a novel approach for ensuring correctness of agentic coding output.

### Karpathy’s Pelican - (Hacker News)

https://twitter.com/karpathy/status/2083749667410727319

# Summary

Andrej Karpathy shared an experiment where Claude Opus 5 generated a Three.js 3D visualization of the Lord of the Rings opening paragraph, producing 5,500 lines of procedural code that rendered the story with animated assets. This demonstrates LLMs moving beyond simple benchmarks—the model orchestrated complex 3D coordinates and animations despite the inherent difficulty. Karpathy highlights this as an example of economically viable custom content creation that would be impractical for humans to undertake manually, enabling future applications like personalized interactive game worlds where users could participate in favorite stories as NPCs or characters.

However, Karpathy also identifies a significant weakness: LLMs struggle to audit their work in game and video domains because they cannot efficiently perceive or interact with dynamic visual content. In this case, Opus 5 had to laboriously capture screenshots to verify its output, leading to some errors and visual artifacts. He emphasizes that improved multimodal and gameplay capabilities remain crucial gaps in current AI development.

### Show HN: ssh ssh.place - (Hacker News)

https://ssh.place

# Summary

ssh.place is an interactive collaborative drawing canvas accessible via SSH with no signup required. Users can connect with any SSH key to a 200×60 cell grid where they can place colored pixels, with each user limited to one placement every 15 seconds. The interface uses simple keyboard controls (arrow keys or vim-style navigation) to move around the canvas and number keys to select from 16 colors.

The project emphasizes simplicity and accessibility—no installation, no account creation, and no text allowed (only visual drawings). The cooldown timer is tied to individual SSH keys, preventing users from bypassing the rate limit by reconnecting, and the canvas can only be modified through SSH, making it a pure collaborative drawing experience that currently has 8,068 out of 12,000 cells drawn.

### Why we write our own C and C++ inference engines - (Hacker News)

https://localai.io/blog/why-we-write-our-own-engines/

# Summary

LocalAI has developed 18 custom C and C++ engine ports rather than wrapping existing Python-based inference frameworks, because this approach enables dramatically smaller deployments while maintaining performance parity. For example, their vllm.cpp port produces a 66 MB binary compared to vLLM's 9.1 GB Python install, achieves comparable or slightly better throughput on GPUs, and uses less memory. Other ports like depth-anything.cpp run faster than PyTorch on CPU by optimizing host-side operations that Python implementations never bothered to optimize, though GPU performance typically matches reference implementations.

The development methodology prioritizes correctness first by converting weights into single GGUF files, then porting the computation graph while validating against reference outputs component-by-component before optimizing. This careful approach ensures bit-for-bit compatibility with originals (critical for biometric systems) and prevents shipping incorrect but fast implementations. However, this strategy comes with maintenance costs—each engine requires its own repository, CI, benchmarking suite, and conversion scripts—so LocalAI only builds custom engines when models lack C++ implementations, Python dependencies are prohibitively heavy, or necessary functionality doesn't exist elsewhere.

### CP/M-386 – CP/M for 386 protected mode, derived from CP/M‑68K - (Hacker News)

https://github.com/johnsonjh/cpm386

# Summary

CP/M-386 is an early-stage operating system that brings CP/M (a classic 1970s-80s OS) to 386 protected mode, derived from CP/M-68K. It features full 32-bit protected mode with Ring-3 TPA, is bootable via floppy disk or GRUB, and supports VGA text and serial console interfaces. The system achieves 100% BDOS compatibility with CP/M 2.2 and CP/M-68K 1.3, along with significant support for CP/M-Plus and other variants, though it currently lacks drivers for storage and network devices.

The project is open-source and compiles on Linux, NetBSD, and FreeBSD systems using standard GNU tools (GCC, Make, NASM). It produces bootable floppy images and Multiboot kernel binaries that can be tested in QEMU emulation, and includes numerous utility programs demonstrating system functionality like file operations, graphics, fractals, and memory management.
