### In-House LLM Serving at Netflix - (Python Weekly)

https://netflixtechblog.com/in-house-llm-serving-at-netflix-a5a8e799ea2c

# Summary

Netflix built an in-house LLM serving platform that integrates with their existing production infrastructure rather than using external APIs. The system uses vLLM as the inference engine integrated into NVIDIA's Triton Inference Server, with a Java control plane managing deployment, versioning, and multi-region rollouts. Key architectural decisions included selecting vLLM for its extensibility and custom decoding support, choosing the vLLM backend for model packaging to decouple model and frontend evolution, and exposing both OpenAI-compatible HTTP and gRPC APIs so LLMs are treated like any other model type in their system.

The platform employs two deployment strategies—Red-Black for stable interfaces and Versioned for schema changes—to enable smooth rollouts on GPU infrastructure. Production revealed important operational considerations, including the need to pin compatible Triton/vLLM versions, pre-cache large models on shared storage to reduce cold-start times, and patch Triton's frontend to properly handle constrained decoding (like JSON output formatting). This design philosophy of integrating LLMs into the broader ML serving stack rather than siloing them has enabled Netflix to smoothly transition workloads from hosted APIs to self-hosted models.

### Releases now reject new files after 14 days - (Python Weekly)

https://blog.pypi.org/posts/2026-07-22-releases-now-reject-new-files-after-14-days/

# Summary

PyPI now rejects new file uploads to releases older than 14 days to prevent attackers from poisoning stable releases if project credentials are compromised. This policy was implemented following security incidents involving popular packages like LiteLLM and Telnyx that were compromised through vulnerable GitHub Actions workflows. The restriction addresses a previously unprotected vulnerability with no technical barriers to exploitation.

The change had been under discussion since January 2024 but faced resistance from projects needing to add support for new Python versions to existing releases. However, PyPI's analysis of 15,000 packages revealed only 56 projects (0.37%) had uploaded files to old releases more than 14 days after publication. With this data and consensus from the Packaging Summit at PyCon US 2026, the restriction was implemented in July 2026 to reduce security risks and administrative cleanup work from compromises.

### Building Agentic Workflows in Python with LangGraph - (Python Weekly)

https://machinelearningmastery.com/building-agentic-workflows-in-python-with-langgraph/

# Summary

LangGraph is a Python framework for building agentic AI workflows that handle complex, multi-step interactions beyond simple single-turn model calls. The article explains that LangGraph represents agents as graphs composed of three core components: **state** (shared memory as a TypedDict), **nodes** (Python functions that read and update state), and **edges** (connections defining execution order). It uses `MessagesState` for automatic conversation history management and reducers to accumulate messages across nodes rather than replacing them.

The article provides practical guidance on building agents from scratch, including how to initialize the model within a node, register tools for the agent to use, route tool calls back through the reasoning loop, and persist conversations across separate invocations using checkpointers. This architecture makes the entire execution flow visible and inspectable, solving common challenges in agent development like context management, tool integration, and conversation continuity without requiring custom implementation for each use case.
