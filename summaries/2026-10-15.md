### Grafana Tempo 3.1 Adds Query-Based Trace Redaction and Sampling-Aware TraceQL Metrics - (InfoQ)

https://www.infoq.com/news/2026/10/grafana-tempo-31/

# Summary

Grafana Tempo 3.1 introduces several enhancements to its distributed tracing system, building on the Kafka-based architecture introduced in version 3.0. Key improvements include expanded Kafka client support with TLS, mTLS, and multiple SASL mechanisms (SCRAM-SHA-256/512, OAUTHBEARER, AWS_MSK_IAM), enabling compatibility with services like Azure Event Hubs. The release also adds query-based trace redaction using TraceQL queries instead of manual trace ID enumeration, allowing operators to redact sensitive data across multiple traces more efficiently.

Additionally, Tempo 3.1 enhances TraceQL metrics with sampling-aware capabilities through an experimental `extrapolate=true` hint that corrects metrics by accounting for sampling rates, arithmetic operations between metrics and scalars, and improved query performance. The vParquet5 block format becomes the default, delivering approximately 50% faster query execution for simple metrics queries. These updates maintain backward compatibility while improving operational efficiency and security for trace data management.

### Article: Server-Side DPoP and Token Exchange in Spring Security 7 - (InfoQ)

https://www.infoq.com/articles/spring-security-7-server-side-dpop-token-exchange/

# Summary

Spring Security 7 consolidates the previously standalone Spring Authorization Server, bringing OAuth 2.0/OIDC server capabilities directly into Spring Security with production-ready implementations of two key RFC standards: DPoP (Demonstrating Proof of Possession) for sender-constrained tokens and RFC 8693 Token Exchange for standardized delegation grants. The migration from Spring Boot 3 to Spring Boot 4 (paired with Spring Security 7.1) requires attention to breaking changes, particularly that resource-server DPoP verification is no longer automatic and must be explicitly enabled with the new `.dPoP()` call.

The article focuses on how these two features work together to enable secure service-to-service and agentic architectures. DPoP binds tokens to the client's public key, while Token Exchange standardizes the "service-account swap" pattern with subject and actor token semantics to record delegation chains. Spring handles most configuration automatically (JWK thumbprint binding and refresh token binding), leaving developers to decide on nonce policies and whether to replace the default in-memory replay cache with a distributed implementation for clustered deployments. The combined DPoP + Token Exchange pattern is most powerful for issuing narrowed, audience-restricted downstream tokens, though security depends heavily on the exchange policy and token customization logic implemented.

# Summary

Hillel Wayne demonstrates how formal methods principles enable software engineers to identify critical architectural bugs in systems before they're built, without requiring complex mathematics. ### ZCS Command Injection via SNMP Handlers Enables Unauthenticated Remote Code Execution - (InfoQ)

https://www.infoq.com/news/2026/10/zimbra-command-injection/

# Summary

A critical remote code execution vulnerability (CVE-2026-73570, CVSS 8.9) has been discovered in Zimbra Collaboration Suite's SNMP notification system, allowing unauthenticated attackers to execute arbitrary commands on affected mail servers. The flaw stems from improper input sanitization in the swatchdog log monitoring utility, which passes user-controlled SMTP header data directly to shell execution without proper escaping, enabling command injection through special characters like semicolons and backticks.

The vulnerability was quietly patched in July 2026 but not publicly disclosed until August, during which time threat actors reverse-engineered the fix and launched active exploitation campaigns. Attackers use the vulnerability to deploy web shells, extract administrative credentials, and export complete mailbox archives to external cloud storage. Mitigation requires upgrading to Zimbra version 10.1.20 or disabling the SNMP service package entirely.

### AWS Reworks EventBridge Custom Buses for Enterprise-Scale Event-Driven Architectures - (InfoQ)

https://www.infoq.com/news/2026/10/aws-eventbridge-scaling/

# Summary

AWS has introduced an enhanced Custom Event Bus for Amazon EventBridge designed to simplify enterprise event-driven architectures across multiple AWS accounts. The new model allows organizations to create a central, shared event bus that multiple teams can publish to and subscribe from using AWS Resource Access Manager (RAM), eliminating the need for complex cross-account connections and forwarding configurations. Key improvements include native event ordering, retention (1-365 days), replay capabilities, content-based deduplication, and a new Subscriber resource that consolidates filtering, retries, and dead-letter configurations into a single definition.

This redesign addresses the governance and cost challenges that emerge when event-driven architectures scale across teams and accounts. By positioning a central bus as an organizational backbone while allowing individual teams to manage their own subscriptions and consumption patterns, AWS shifts responsibility from platform teams (who manage infrastructure connections) to application teams (who manage their own event consumption). The enhanced bus also supports synchronous Lambda invocation and JSONata transformations, making it suitable for diverse workload patterns while the new pricing model (based on ingress/egress throughput) prevents costs from compounding through multiple forwarding hops.

### Cloudflare’s OHTTP Gateway Refuses to Decrypt Requests That Arrive through Cloudflare - (InfoQ)

https://www.infoq.com/news/2026/10/cloudflare-ohttp-gateway/

# Summary

Cloudflare has launched a closed beta of its OHTTP Gateway, a service that decrypts Oblivious HTTP requests (RFC 9458) on behalf of origin servers. The gateway notably refuses to decrypt requests that originate from Cloudflare Workers or pass through Cloudflare's proxy, maintaining a key security principle: the relay and gateway must be operated by separate, non-colluding parties. This design ensures that while the gateway sees request content but only the relay's IP address, and the relay sees the client's IP but not the request contents, these two identifying hops cannot be combined by a single operator.

The practical implication is that organizations adopting OHTTP must provide their own relay infrastructure, though Cloudflare positions this as straightforward. The Gateway binds to a fixed path and manages encryption keys, while offering integration with Cloudflare Access for relay authentication. However, OHTTP only provides network-level privacy and doesn't encrypt request bodies, so users must avoid sending identifying information within encrypted payloads. The protocol addresses a specific use case: hiding client identity while preventing correlation of multiple requests from the same user.

### When Architecture Decisions Actually Apply - (Radar)

https://www.oreilly.com/radar/when-architecture-decisions-actually-apply/

# Summary

The article discusses the critical distinction between architectural decisions being *relevant* versus having *authority* over a specific code change. The author illustrates this through an example where an AI coding agent retrieved a decision ruling out PostgreSQL for a command-line tool but still proposed using PostgreSQL anyway. The problem wasn't retrieval failure—the decision was found and timely—but rather the system lacked an "applicability signal" to determine that this decision actually governed the storage module being edited.

The author argues that effective architectural governance requires two separate mechanisms: retrieval (finding potentially relevant decisions through search) and applicability determination (establishing which decisions have actual authority over a specific artifact). True applicability requires considering scope, lifecycle, precedence, and clear records of decision replacements. Simply surfacing relevant architectural information to an AI agent is insufficient; systems must explicitly track and enforce which decisions actually apply to particular code changes.

### Designing Websites for People and AI Agents with WebMCP - (Radar)

https://www.oreilly.com/radar/designing-websites-for-people-and-ai-agents-with-webmcp/

# Summary

WebMCP is a new standard that enables web developers to create structured tools accessible to AI agents, bridging the gap between how humans and AI interact with websites. Rather than forcing agents to interpret screenshots or analyze page structure, developers can register tools through a simple API that defines the tool's name, description, input schema, and execution function. This reduces token usage and interpretation errors while allowing agents to call website functions with structured inputs.

The standard offers both programmatic and declarative approaches—developers can register tools dynamically via JavaScript or use HTML attributes on existing forms. A key design principle is keeping humans and agents in the same interface: tools can be registered based on page state, and forms can be configured to let agents populate fields while leaving the final action for human confirmation, ensuring people remain in control of their interactions.
