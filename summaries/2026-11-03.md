https://www.infoq.com/news/2026/11/linkedin-opentelemetry-journey/

# Summary

LinkedIn has developed an OpenTelemetry-based telemetry platform that connects user interactions on mobile and web clients with backend service processing, closing a gap in observability. The platform traces member journeys from initial user actions through frontend and backend services to data stores, using a novel `pageForestId` to group related requests from a single page alongside individual trace IDs, allowing engineers to investigate both individual requests and broader user experiences.

### Google and Meta Open-source TorchTPU to Bring Native PyTorch Support to Google TPUs - (InfoQ)

https://www.infoq.com/news/2026/11/torchtpu-native-pythorch-tpu/

# Summary

Google and Meta have open-sourced TorchTPU, a native PyTorch backend that enables PyTorch workloads to run on Google TPUs with minimal code modifications. Unlike the previous PyTorch/XLA approach (which required intrusive source-code changes and suffered from compile-time latency), TorchTPU prioritizes eager execution and supports three execution modes: strict, debug, and a new hybrid "DeferAndFuse" mode that can be 50% faster while reducing memory usage.

The project has been extensively tested on thousands of Hugging Face models across multiple TPU hardware generations, with demonstrated strong performance on both inference and training tasks. Migration from GPU to TPU requires only simple changes like replacing "cuda" with "tpu" device identifiers, or using a new device-agnostic API. While still in early stages, TorchTPU represents a significant step forward in making TPU hardware more accessible to the PyTorch ecosystem.

### Uber Builds MCP Gateway to Govern Access to 800+ Servers and 5,000+ AI Agent Tools - (InfoQ)

https://www.infoq.com/news/2026/11/uber-mcp-gateway-ai-agents/

# Summary

Uber has developed an MCP Gateway to standardize how AI agents access and invoke internal services at scale, addressing fragmentation and security inconsistencies as agent adoption grows. The platform manages over 800 MCP servers and 5,000 tools through a microservice architecture comprising an MCP Registry (control plane) and Proxy Gateway (runtime execution). The registry maintains tool definitions and schemas, while the proxy translates between MCP and various backend protocols (HTTP, gRPC, TChannel), providing centralized discovery, authorization, PII redaction, and access control.

To manage the growing catalog efficiently, Uber implemented AutoCrawler to automate tool discovery from internal API registries and automatically generate MCP-compatible schemas, and Omni MCP to enable incremental tool discovery and selective schema retrieval. The solution draws parallels to established API gateway patterns, with observers noting it applies decades-old distributed systems principles—including security, observability, and governance—to the emerging challenge of governing AI agent tool access.

### Article: Systemic Approach to Memory, Knowledge, and Context in Agentic AI Architectures - (InfoQ)

https://www.infoq.com/articles/agentic-ai-context-memory-knowledge/

# Summary

This article presents a systemic framework for building reliable agentic AI systems by distinguishing between three critical components: **context** (immediate, active information in the model's processing window), **memory** (persistent information retained across interactions), and **knowledge** (curated foundational facts and rules). The author argues that as AI systems evolve from chatbots to autonomous agents, the architectural focus must shift from prompt engineering to context engineering—specifically, designing systems that intelligently select, inject, compress, and expire information before it reaches the model.

The article emphasizes that effective agentic AI architecture requires treating context as a "control plane" that governs system operations through organizational, behavioral, and situational data. Key principles include balancing historical data with real-time signals, optimizing rather than maximizing context size, and recognizing that hallucinations typically stem from context failures rather than model limitations. The framework addresses common anti-patterns like context stuffing and stale data loops, advocating for tiered memory management and token budgeting to ensure agents act as reliable software systems rather than unpredictable black boxes.

### Shopify Overexposed Scans GKE Ingresses and Cloud Run for Exposure - (InfoQ)

https://www.infoq.com/news/2026/11/shopify-kubernetes-ingresses/

# Summary

Shopify developed Overexposed, an internal security scanner that identifies publicly accessible Kubernetes Ingresses on Google Kubernetes Engine (GKE) and Cloud Run services without authentication. After an initial version based on repository configuration files produced high rates of false positives and missed vulnerabilities, the team rebuilt it using GCP Cloud Asset Inventory and anonymous HTTP probing, which reduced inconclusive verdicts by approximately 80% within weeks of tuning.

The improved scanner queries Cloud Asset Inventory for accepted infrastructure configurations and access policies, then probes each candidate with HEAD/GET requests to determine exposure status. It classifies findings into six verdicts (exposed, expected, protected, not found, unreachable, inconclusive) and accounts for context-dependent HTTP status codes. The scanner includes security hardening against SSRF attacks and distinguishes between ingress settings and IAM permissions when evaluating Cloud Run services. This practical approach demonstrates the importance of validating actual cluster enforcement rather than relying solely on configuration file intent.

### File Mover Express: AWS Releases Open-Source Tool for S3 File Transfers - (InfoQ)

https://www.infoq.com/news/2026/11/aws-s3-file-transfer/

# Summary

AWS has released File Mover Express, an open-source tool (Apache 2.0 license) designed to efficiently transfer large files between local systems and Amazon S3. Available for macOS, Windows, and Linux, the application features parallel transfers with automatic performance tuning, pause/resume capability, file integrity verification via multiple checksum algorithms, and both a graphical UI and scriptable CLI interface. The daemon-based architecture allows transfers to continue independently of desktop sessions.

The tool addresses pain points for media teams who regularly move terabytes of assets to the cloud by offering advantages over traditional clients and commercial alternatives, including no licensing costs and no reliance on proprietary protocols. Key security features include end-to-end encryption, IAM-based access control, OIDC single sign-on support, and optional S3 Transfer Acceleration for distant buckets. The project is built in Go for the transfer engine and TypeScript/Angular for the GUI, with source code available on GitHub.

### Cloudflare’s Post-Quantum GeoKey Manager Enters Closed Beta without Attribute-Based Encryption - (InfoQ)

https://www.infoq.com/news/2026/10/cf-pq-geokey-manager/

# Summary

Cloudflare has entered closed beta testing for a post-quantum redesign of its GeoKey Manager service, which protects geographically restricted decryption keys using a hybrid encryption approach combining ML-KEM-768 and X25519. The new system replaces attribute-based encryption (used since 2022) with a simpler model based on HPKE (Hybrid Public-Key Encryption), addressing both data sovereignty requirements and protection against harvest-now, decrypt-later quantum attacks. The beta is available to existing Data Localization Suite customers, with general availability expected in Q1 2027.

The redesigned system uses two types of keys: regional root keys stored securely in kernel memory and application-specific key pairs derived per service and epoch. Keys are distributed through separate paths and protected by multiple verification checks (TPM identity, inventory lookup, and provisioning service approval) before reaching edge servers. The architecture intentionally implements a fail-closed design—any security check failure or missing keys will reject service requests—which Cloudflare considers a critical safety feature, though some security experts have raised concerns about potential regional outages and the blast radius of compromised components.

### OpenBSD 8.0 Brings Expanded Hardware Support, Security Enhancements, and Virtualization Improvements - (InfoQ)

https://www.infoq.com/news/2026/10/openbsd-8-released/

# OpenBSD 8.0 Summary

OpenBSD 8.0 is a major release featuring significantly expanded hardware support, enhanced security, and improved virtualization capabilities. Key improvements include a larger virtual address space for AMD64 kernels (expanded from 4 GB to 512 GB), support for Intel Arc A-Series GPUs, multi-processor virtual machines with up to 64 vCPUs, enhanced RISC-V support, ARM64 hibernation, and numerous new peripheral drivers. The release also upgrades security components with LibreSSL 4.4.0 and OpenSSH 10.6, maintaining OpenBSD's exceptional security track record of over 30 years with only two remote holes in default installations.

Beyond hardware and security improvements, OpenBSD 8.0 enhances the httpd daemon with custom HTTP headers and improved HTTPS crypto methods, while continuing to emphasize the system's simplicity and adherence to Unix philosophy. However, NVIDIA GPUs remain unsupported due to lack of proprietary driver availability, and the system still lacks advanced filesystem support like ZFS or Btrfs, making it potentially less suitable for large-scale server deployments despite its renowned stability.

### Kubernetes Confidential Containers Get Fortanix Attestation and Key Management - (InfoQ)

https://www.infoq.com/news/2026/10/k8s-confidential-containers/

# Summary

Fortanix has integrated its Confidential AI platform with Kubernetes Confidential Containers (CoCo), a Cloud Native Computing Foundation project that runs pods inside hardware-based trusted execution environments (TEEs). The integration connects workload attestation to encryption-key management, allowing only verified workloads to decrypt sensitive models and data. Fortanix's solution uses its Confidential Computing Manager (CCM) to verify the environment and Data Security Manager (DSM) to release keys only after successful attestation, eliminating the need for teams to build their own trust layer.

While CoCo and Fortanix's approach provide enhanced data-in-use protection for sensitive workloads on shared infrastructure, the solution has limitations. Teams must still trust the guest kernel and helper processes within the security boundary, and attestation alone doesn't guarantee safe data handling by applications. Fortanix offers CCM and DSM as a hosted, on-premises, or air-gapped service with 24/7 support, with deployment guides for Intel TDX and AMD SEV-SNP processors.

### LocalStack for Azure Enters Public Preview with Security Settings Stored but Not Enforced - (InfoQ)

https://www.infoq.com/news/2026/10/localstack-azure-preview/

# Summary

LocalStack has released its Azure emulator into public preview, allowing developers to test Azure applications locally without needing Azure subscriptions or incurring costs. The tool accepts existing ARM and Bicep templates, Terraform modules, and Azure CLI scripts, supporting a broad range of Azure services including AKS, Functions, App Service, Cosmos DB, and Key Vault. Each developer gets an isolated sandbox environment, with general availability expected in early 2027.

However, the emulator has significant limitations that developers should be aware of. While security settings and configurations are stored and returned by the emulator, they are often not actually enforced—for example, httpsOnly settings don't prevent HTTP access, authentication policies aren't enforced, and network security rules aren't applied. The documentation candidly details these gaps across different resource providers, indicating that applications passing locally on LocalStack may still fail when deployed to actual Azure. Additionally, Windows-based web apps run on Linux runtime, Apple Silicon deployments can fail, and application state is lost when the emulator stops.

### The Monday Morning Agent: Defining the Tush Push - (Radar)

# Summary

This article discusses how to properly define ambiguous terms before using AI agents to analyze data, using the NFL's "tush push" controversy as a case study. The authors emphasize the importance of creating clear, plain-language definitions in a shared data dictionary before querying data, then testing whether the available data can actually support that definition. They identified five possible interpretations of the tush push and settled on "quarterback run with one yard or less to go, from under center," while explicitly documenting what the data cannot measure (like whether an actual push occurred).

The article advocates for a systematic approach to AI-assisted analysis that includes: writing down definitional limitations, enforcing consistent definitions across multiple runs through a locked data dictionary, and building in checks to verify the agent actually uses the stored definition. This prevents subtle meaning shifts and ensures reproducibility while making readers aware of the gap between the measured proxy and the actual phenomenon being studied.

### Practical Loop Engineering - (Radar)

https://www.oreilly.com/radar/practical-loop-engineering/

# Summary

This article discusses "loop engineering," a technique for working with AI agents that involves setting up autonomous, self-correcting feedback cycles where agents repeatedly act, test results, and adjust their approach until goals are met. The author, Addy Osmani, explains how he typically runs multiple agents in parallel while maintaining oversight, using clear stopping conditions and constraints. He notes that loop engineering has evolved from manually constructed bash loops to built-in primitives in Claude Code, such as goal-driven tasks and timer-based reruns.

The article emphasizes the importance of careful oversight when using loops, warning that leaving them unattended without well-defined goals and constraints can create problems. The Claude Code team has categorized different types of loops based on how they're triggered and stopped, recommending that developers start with the simplest solutions and use loop patterns selectively rather than defaulting to complex automation for all tasks.
