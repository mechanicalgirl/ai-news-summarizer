### Tracing np.add, all the way down - (Python Weekly)

https://blog.veitheller.de/numpy.html

# Summary

This article traces the execution of `np.add(a, b)` through NumPy's source code, from the Python function call down to the actual SIMD kernel that performs the addition. The author explains that `np.add` is not a regular Python function but a `ufunc` object containing multiple inner loops for different data types. The execution path involves several steps: parsing arguments, checking for `__array_ufunc__` overrides (allowing third-party libraries like Dask to intercept), dispatching to find the correct `dd->d` (double-to-double) loop implementation, and caching the result for future calls.

The final stages involve choosing an iteration strategy—either a "trivial loop" that processes entire arrays without overhead if shapes match, or a more complex iterator for general cases. The article emphasizes that while the mental model of "it adds arrays in C, quickly" is correct, substantial machinery exists to route the call to the appropriate compiled function, including type promotion, caching mechanisms, and adaptive iteration strategies that optimize common cases.

### KV, Prefix, Prompt and Semantic Caching in LLMs, clearly explained - (Python Weekly)

https://x.com/_avichawla/status/2093265776266637739

# Summary

This article explains four different caching mechanisms in large language models (LLMs) that store different objects: the KV cache (stores attention tensors for one request), prefix caching (stores tensors on the server keyed by hash chains), prompt caching (the provider's billed version at reduced input rates), and semantic caching (stores finished responses using fuzzy matching). The first three use exact matching and are correctness-neutral, so cache misses cost money and latency, while semantic caching uses fuzzy matching and risks returning incorrect answers.

The article provides detailed explanations of how each cache works, starting with the KV cache, which stores key and value vectors computed during the prefill phase to avoid recomputation during token generation. It then covers prefix caching in serving engines like vLLM, which keeps KV blocks in memory and reuses them across requests using hash-based lookup chains. The author explains the trade-offs, optimization techniques (like cache quantization and grouped-query attention), and common issues that break cache reuse, such as editing chat history or mismatched token sequences. Code examples demonstrate how to implement these caches using the transformers library.

### Unit testing with wrapture - (Python Weekly)

https://grahamdumpleton.me/posts/2026/09/unit-testing-with-wrapture/

# Summary

This article compares unit testing approaches using `unittest.mock` versus `wrapture`, a Python testing tool that wraps real code rather than replacing it. The author demonstrates their differences through testing an order service that charges payments, records them in a ledger, and sends notifications.

While both tools handle basic stubbing similarly, `wrapture` offers significant structural advantages: it enforces strict signature checking by default (preventing tests from passing with invalid calls), can observe internal method calls that mocks cannot see, allows real code to run while selectively modifying arguments or results, and provides clearer assertions on absence of calls with real values rather than fabricated mock objects. For error-path testing specifically, `wrapture` shines by letting developers assert against actual charge IDs and verify call ordering across multiple objects, while mocks require working with invented values and multiple fake objects. The key insight is that wrapping enables tests to be more precise about what actually happens in production code.

### When to use NotImplemented - (Python Weekly)

https://www.pythonmorsels.com/when-to-use-notimplemented/

# Summary

`NotImplemented` is a special value that dunder methods should return when they cannot perform an operation on a given object type. When Python encounters `NotImplemented`, it delegates the operation to the other object's corresponding method (e.g., if `a.__add__(b)` returns `NotImplemented`, Python tries `b.__radd__(a)`). This allows operations like `3 + 3.0` to work seamlessly by letting the floating-point object handle the operation when the integer cannot.

When implementing your own dunder methods, return `NotImplemented` instead of `False` or raising an exception if you don't know how to operate on the other object's type. This prevents inconsistencies—for example, if you returned `False` for unknown types, you could end up with asymmetrical comparisons where `a == b` is `True` but `b == a` is `False`. Using `NotImplemented` ensures Python properly delegates to the other object, maintaining logical consistency in operations.

### The sameness problem behind those unappetizing AI-generated menus - (TechCrunch)

https://techcrunch.com/2026/09/03/the-sameness-problem-behind-those-unappetizing-ai-generated-menus/

# Summary

AI-generated restaurant menus are becoming noticeably off-putting to consumers due to a "sameness problem" rooted in how these models are trained. Large language and diffusion models learn patterns from vast datasets, often containing similar existing menus (like those from major chains) and increasingly their own AI-generated outputs. This creates a feedback loop of convergence where food illustrations become increasingly homogenized, overly smooth, and perfectly symmetrical—eliciting an uncanny valley effect that feels unsettling even when consumers can't articulate why.

The issue stems from AI models' tendency to optimize for "pleasingness" and avoid offensiveness, which paradoxically strips away the natural imperfections that make real food look appetizing. Additionally, when restaurants repeatedly edit AI-generated menus, each revision further smooths and rounds the images. Research shows people intuitively sense something is wrong with AI-generated imagery, and the broader cultural context around AI deepens consumer skepticism about trusting visual evidence, raising implications beyond just dinner menus.
