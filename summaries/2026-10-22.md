### Presentation: Actors for Agents: Patterns for Production AI - (InfoQ)

https://www.infoq.com/presentations/actors-for-production-ai-agents/

# Summary

This article, featured on InfoQ, presents a talk by Manju Rajashekhar on applying the actor model to production AI agents. Rajashekhar argues that the actor model—traditionally used for distributed systems—effectively addresses the runtime challenges of production AI agents by managing state ownership, message passing, fault handling, and execution continuity. He emphasizes that while simple prompt-chain architectures work for demos, moving agents to production requires treating them as distributed systems with proper supervision boundaries and state management to create resilient, long-running agentic workflows.

The speaker, a veteran engineer from Twitter and former VP of engineering at Etsy, draws on extensive experience scaling distributed systems to explain how actor-based patterns can transform fragile demo architectures into production-ready systems. His talk advocates for moving beyond simple sequential agent designs toward more sophisticated architectural patterns that handle failures, manage mutable execution graphs, and maintain reliable long-horizon agent execution in real-world environments.

### Article: AI Changes the Data Interface, Not the Query Engine - (InfoQ)

https://www.infoq.com/articles/ai-changes-data-interface/

# Summary

This InfoQ article by Peihao Yuan argues that AI agents don't eliminate the need for query engines and data infrastructure—they simply change how users interact with them. Using a real-world disaster-recovery analysis example, the author demonstrates that AI agents still require deterministic computation engines (like DuckDB) to perform precise filtering, aggregation, and joining operations. AI changes the interface and interpretation layer, allowing natural language queries instead of SQL, but the underlying need for accurate data processing remains.

The article advocates for separating deterministic computation from probabilistic reasoning: let engines handle precise calculations while AI agents interpret results and communicate conclusions. The author provides practical guidance for choosing between embedded engines (like DuckDB) for moderate data volumes with single consumers versus managed lakehouses for enterprise scenarios with multiple users, concurrent writes, and governance requirements. Production-grade agent analytics should retain source data, configurations, and outputs to enable validation and replay of every report.

### Harbor Adds Docker Sandboxes to Run Reproducible AI Agent Evals in Isolated MicroVMs - (InfoQ)

https://www.infoq.com/news/2026/10/ai-agents-harbor-docker/

# Summary

Docker has integrated Harbor, an open-source AI agent evaluation framework, with Docker Sandboxes to enable reproducible testing of AI agents in isolated microVMs. Each evaluation task now runs in its own sandboxed environment with its own kernel, preventing agents from accessing the host system, other tasks, or external resources. This isolation addresses key challenges in AI agent evaluation, including preventing "reward hacking" (where agents game tests rather than solving problems) and ensuring reproducible results by maintaining consistent network conditions across evaluations.

The integration is available in Docker Sandboxes' nightly release and will reach stable release on October 23. Harbor supports both local execution (free) and cloud scaling through Docker Cloud Sandboxes, which Docker has tested with 64 concurrent tasks. Teams using Harbor can now select sandboxed environments with a simple flag (`-e sbx`), with finer-grained network policies available in the cloud version to ensure fair agent comparisons. However, the announcement lacks specific data on startup overhead, per-task costs, and performance metrics that teams may need to evaluate before adopting the cloud option.

### eMudhra Intermediate CA Compromise - (InfoQ)

https://www.infoq.com/news/2026/10/emudhra-ca-compromise/

# Summary

eMudhra's private keys for eight intermediate Certificate Authority (CA) certificates were compromised due to insecure key generation—the keys contained minimal entropy with only the final byte varying. Six of these certificates were trusted for TLS by major root programs (Apple, Chrome, Microsoft, Mozilla), and two were used for codesigning and trusted by Microsoft. This compromise allowed attackers to forge certificates that would be trusted by unpatched systems, potentially enabling man-in-the-middle attacks to impersonate legitimate sites and services.

The response involved browsers quickly blocking the affected CAs using revocation blocklists, but most other software lacked similar filtering mechanisms. Many projects removed the emSign ECC Root CA from their trust stores, causing collateral damage to legitimate certificates. Updates to CA certificate bundles have been distributed across major Linux distributions, programming languages, and frameworks, but propagation is slow, leaving unpatched and end-of-life systems vulnerable. The broader issue highlights the inherent weakness of large trust anchor systems where hundreds of CAs in root bundles and thousands of intermediate CAs can each issue certificates for any domain.

### Netflix Bridges AWS IAM and Internal Identity with Workload Attestation - (InfoQ)

https://www.infoq.com/news/2026/10/netflix-workload-attestation-aws/

# Summary

Netflix has developed a workload attestation system that bridges AWS IAM with its internal Metatron PKI infrastructure, enabling Apache Spark jobs on Amazon EMR to securely exchange their AWS execution identity for short-lived internal workload credentials. The solution maps each Data Project to a dedicated IAM role and uses a control plane to create signed metadata payloads that are verified against AWS Security Token Service responses, allowing the Identity service to issue the appropriate Metatron certificates.

The architecture efficiently handles Spark's distributed nature by having only the driver attest once and distribute credentials to executors through authenticated encrypted RPC, rather than attesting thousands of executors independently. This approach separates organizational identity from cloud provider identity while maintaining cryptographic proof of the cloud identity, and Netflix notes it could apply to other managed compute environments facing similar identity integration challenges.

### Article: Distributed Spring Batch Without a Message Broker - (InfoQ)

https://www.infoq.com/articles/spring-batch-without-broker/

# Summary

This article explores how Spring Batch, a popular JVM batch processing framework, can be scaled horizontally across multiple nodes without requiring a separate message broker. Instead of using systems like Kafka or RabbitMQ for coordination, the approach leverages the relational database that Spring Batch already requires for its job repository. The solution addresses four core distributed computing challenges: dividing work appropriately across available workers, assigning a master node for each job run, ensuring partitions are claimed by only one worker (preventing duplicate execution), and handling node failures through heartbeat monitoring and two-phase recovery.

The pattern enforces a correctness contract where transferable work runs at least once and must be idempotent, while non-transferable work runs at most once and fails rather than migrates. This database-coordination approach suits small-to-medium clusters where operational simplicity and cost are priorities, though the author acknowledges that message brokers remain superior for very large clusters or sub-second latency requirements.

### Cilium 1.20 Expands Gateway API and Opens eBPF Datapath for Kubernetes - (InfoQ)

https://www.infoq.com/news/2026/10/cilium-120-kubernetes-networking/

# Summary

Cilium 1.20 significantly expands Kubernetes networking capabilities through three major enhancements. The release upgrades Gateway API support from version 1.4 to 1.6, introducing features like ExternalAuth for external authorization, TCPRoute and UDPRoute for non-HTTP services, and ListenerSets to enable application teams to manage listeners independently while platform teams maintain central control. This makes Gateway API a more comprehensive traffic management layer for various workload types including databases and DNS.

Additionally, Cilium 1.20 opens its eBPF datapath to third-party plugins, allowing cloud providers and operators to build custom networking behavior without maintaining separate forks. The release also introduces automatic pod datapath selection, which intelligently uses the newer netkit network device on compatible kernels (6.8+) while falling back to traditional veth pairs on older systems, eliminating the need to partition mixed fleets into separate node pools.

### Microsoft Previews dotnetup: Toolchain Manager for .NET SDKs and Runtimes - (InfoQ)

https://www.infoq.com/news/2026/10/dotnetup-preview/

# Summary

Microsoft has released a public preview of **dotnetup**, a cross-platform toolchain manager that allows developers to install, update, and manage .NET SDKs and runtimes within their user account rather than system-wide directories. Following the model of similar tools like rustup and nvm, dotnetup tracks developer intent (such as requesting "latest," "lts," or specific version bands) rather than exact versions, reads the nearest global.json to ensure deterministic team builds, and installs components under the user's local data directory. The tool supports multiple installation modes and can manage preview and daily builds side-by-side.

However, the community response has been mixed, with some praising its simplified Linux setup while others have raised concerns about the curl-to-shell bootstrap method, requested integration with package managers like winget and Homebrew, and noted limitations such as Visual Studio not recognizing dotnetup installations. Microsoft has stated that package manager support is planned after user validation, and the roadmap includes admin-level Windows installs and AI assistant integration.

### TornadoVM 7 Enables GPU-Native Workloads From Java Applications - (InfoQ)

https://www.infoq.com/news/2026/10/tornadovm-7-gpu/

# Summary

TornadoVM 7.3, an open-source heterogeneous GPU programming framework for Java, has reached a major milestone by enabling GPU-native workloads directly from Java applications. The framework automatically accelerates Java programs on multi-core CPUs and GPUs by offloading code to hardware backends, managing memory transfers, and compiling Java to OpenCL and Apple Metal backends. This allows developers to write code once on their laptops and deploy it to servers with Nvidia GPUs for significant performance improvements.

Version 7 introduces substantial architectural improvements, including replacing Java Native Interface (JNI) with the Foreign Function & Memory (FFM) API and removing experimental dependencies for broader JDK compatibility. The release significantly deepens integration with the Nvidia ecosystem through an optimized CUDA backend that supports cuTile programming, direct access to CUDA libraries like cuBLAS and CUTLASS, multi-GPU execution, and Apple's MXL library. TornadoVM is particularly effective for data-parallel workloads and now integrates with major frameworks like Apache Flink, Spring AI, and Quarkus, offering Java developers idiomatic access to GPU-accelerated libraries for tasks like linear algebra, signal processing, and deep neural networks.

### The Second-User Test - (Radar)

https://www.oreilly.com/radar/the-second-user-test/

# Summary

The article discusses "the second-user test"—a practice where a project created by one person is handed off to another to assess whether it remains understandable and functional without the original creator's explanations. Generative AI has made this test more revealing because it enables students to quickly produce polished-looking work (code, analysis, visualizations) that may mask incomplete understanding. Since AI can fill gaps and smooth over rough reasoning, the quality of output no longer reliably indicates genuine comprehension.

The author illustrates this with a concrete example: when a second student was tasked with reproducing a peer's analysis on AI and labor economics, they uncovered critical issues—including poor documentation, hidden dependencies in the workflow, and problematic measurement design where survey items were inappropriately reused in multiple measures. These flaws were invisible in the original polished work but became apparent only when someone else tried to independently verify and rebuild the project. The handoff revealed that true understanding requires rigorous documentation, reproducibility, and the ability to defend methodological choices.

The authors are building an AI agent with progressively more capabilities over eight episodes to investigate claims like "you have to establish the run." The first episode demonstrates key principles: clearly defining what a claim means before analyzing data, giving the agent a specific job you can verify, and transparently showing how data filters affect results.

While teams with high rushing percentages won 77.7% of games overall, this correlation largely reflects teams already ahead running out the clock. The authors emphasize that correlation doesn't imply causation and that the filters applied fundamentally change which conclusions the data supports.

### AI Changed How We Code. It Hasn’t Changed How We Work Together. - (Radar)

https://www.oreilly.com/radar/ai-changed-how-we-code-it-hasnt-changed-how-we-work-together/

# Summary

While AI has dramatically accelerated the coding process through tools like GitHub Copilot and Claude, it hasn't solved the problem of maintaining shared understanding across distributed teams. An intern's experiment called ContextCue highlights a critical gap: as software development speeds up through AI assistance, the context and reasoning behind features often gets lost when work passes between teams across different time zones and locations.

The article illustrates how traditional meeting summaries and transcripts fail to preserve the full context needed by downstream teams—including visual information from screen sharing, decision-making rationale, and the original customer intent. ContextCue attempts to address this by creating richer, portable context that captures not just what was discussed, but why decisions were made, allowing teams to maintain understanding as work moves from one group to another and preventing the loss of crucial meaning in the handoff process.
