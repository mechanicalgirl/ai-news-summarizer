### Inside LinkedIn's cognitive memory agent for agentic personalization - (Stack Overflow Blog)

https://stackoverflow.blog/2026/08/25/inside-linkedin-s-cognitive-memory-agent/

# Summary

LinkedIn built a four-layer cognitive memory system for its hiring assistant agent to provide persistent, personalized state to recruiters. The system comprises conversational memory (immediate session interactions), semantic memory (aggregated user preferences across sessions and products), episodic memory (temporal context with provenance tracing), and procedural memory (how individual users achieve tasks and their specific trade-offs). This layered approach captures user information at different granularities to enable deep personalization beyond simple context retrieval.

The key engineering challenge involves extracting these separate behavioral state markers from a continuous stream of recruiter interactions while preventing context bloat. The team built an ingestion service that consolidates interactions in real-time, identifies session boundaries, and organizes information for discoverability—a task complicated by increasingly complex, non-linear user workflows where recruiters move between job refinement, candidate feedback, and outreach steps rather than following fixed sequential paths.

### Responsible AI adoption needs developer workflow design - (Stack Overflow Blog)

https://stackoverflow.blog/2026/08/24/responsible-ai-adoption-needs-developer-workflow-design/

# Summary

This article argues that responsible AI adoption in organizations requires thoughtful workflow design rather than top-down policies alone. The key insight is that "shadow AI" (unapproved tool use) often signals workflow problems rather than misconduct—when sanctioned processes feel slow or disconnected from actual work, developers naturally seek faster alternatives. The article emphasizes that organizations must make responsible AI use easier and more practical than improvised use.

The article outlines five practical strategies: (1) treat shadow AI as diagnostic evidence to improve systems rather than compliance violations; (2) translate policies into actionable engineering interfaces that answer specific operational questions; (3) embed guardrails directly into development workflows (repositories, pull requests, deployment pipelines) rather than separate portals; (4) assign clear human ownership and accountability for each AI use case throughout its lifecycle; and (5) foster psychological safety so teams can safely report AI failures. Additionally, training should be concrete and job-specific, and success should be measured by outcomes rather than adoption metrics alone.

### Harvest (IBM 7950): Supercomputer for cryptanalysis at the NSA in the Cold War - (Hacker News)

https://spectrum.ieee.org/cold-war-codebreaker-nsa-ibm

# Summary

During the Cold War, IBM built Harvest (IBM 7950) for the NSA—a highly classified supercomputer that processed cryptographic intelligence from 1962 through the mid-1970s. Operating at speeds up to 200 times faster than any other computer of its era, Harvest was designed to automatically process continuous streams of intercepted signals intelligence around the clock, a capability existing batch-processing machines couldn't match. The system paired IBM's Stretch mainframe with a custom streaming coprocessor and featured pioneering innovations including an automated robotic tape library and a specialized programming language called Alpha for describing cryptographic problems.

Harvest represents a significant but hidden chapter in computing history, exemplifying how Cold War national security demands drove technological innovation decades ahead of civilian computing capabilities. As a specialized, single-purpose machine built only once for the NSA's code-breaking operations, Harvest introduced modular architecture and parallel data processing concepts that presaged modern computing approaches like graphics accelerators and real-time data stream processing systems used today.

### Queryable Executables - (Hacker News)

https://fzakaria.com/2026/08/24/actually-queryable-executables

# Summary

Farid Zakaria introduces "Actually Queryable Executables" (SELF), a novel format where programs are SQLite databases rather than traditional binaries. By using Linux's `binfmt_misc` to execute a custom interpreter, the program structure, website content, and application state all collapse into queryable SQL tables within a single executable file. This enables remarkable simplifications: a webserver can store its own code, routes, content, and visitor logs in one file that it can read and modify transactionally while running.

The proof-of-concept `self-httpd` demonstrates this concept as a single-file webserver where routes and content are SQL tables, and user interactions (visits, button presses) are recorded as new rows in the same database file. This approach unlocks benefits including live content editing without restarts, built-in audit trails via `sqldiff`, full-text search capabilities via SQLite's FTS5, and simplified deployment of a single queryable file. Zakaria argues this represents a paradigm shift where the distinction between program and data dissolves, making many traditional systems for managing application state unnecessary.

### OpenAI Jalapeño: Better than Nvidia Blackwell - (Hacker News)

https://newsletter.semianalysis.com/p/openai-jalapeno-better-than-nvidia

# Summary

OpenAI has announced "Jalapeño," a custom-designed inference chip built in partnership with Broadcom that outperforms Nvidia's flagship chips, including Blackwell, across multiple benchmarks. Developed in just 16 months, the chip is a generalized AI inference processor (contrary to claims it's optimized only for OpenAI models) that achieves industry-leading performance-per-watt efficiency without using advanced techniques like speculative decoding or prefill-decode disaggregation. The chip uses HBM4 memory and delivers exceptional token throughput, particularly in low-latency scenarios.

The key differentiator is OpenAI's focus on power efficiency (tokens per megawatt), which aligns with the industry reality that datacenters are power-constrained rather than budget-constrained. While comparisons to Blackwell are somewhat unfair given both chips' different maturity levels, Jalapeño achieves comparable or superior cost-per-token metrics to Nvidia's Vera Rubin chip—and does so without speculative decoding optimizations that could further improve its efficiency. However, the benchmarks are limited to OpenAI's testing and don't yet include the more comprehensive AgentX suite that reflects real production workloads.

### Black hole singularity is a surface not a point - (Hacker News)

https://arxiv.org/abs/2608.21590

# Summary

This paper challenges the common misconception that black hole singularities are point-like objects. Hamilton and McMaken argue that singularities are actually surfaces rather than points, demonstrating that two observers falling into a spherical black hole along different angular paths lose causal contact with each other before reaching the center, despite being spatially close. For rotating black holes, the singular surface likely resides at the inner horizon, where even tiny perturbations trigger mass inflation and collapse to a spacelike singular surface.

The authors propose significant implications for quantum gravity, suggesting that a black hole's quantum states probably reside on its effectively 2-dimensional singular surface, which evolves unitarily in thermodynamic equilibrium with the hot atmosphere of trapped Hawking radiation generated within the event horizon. This reframing of singularities as surfaces rather than points offers a new perspective on black hole physics and quantum gravity theories.

### Maiao: Gerrit-style code review workflow for GitHub, GitLab, Gitea, others - (Hacker News)

https://github.com/runetes/maiao

# Maiao Summary

Maiao is a command-line tool that brings stacked pull requests (a Gerrit-style code review workflow) to multiple git hosting providers including GitHub, GitLab, Gitea, Forgejo, Bitbucket Cloud, and Cursor Origin. It enables developers to break large features into small, independently reviewable commits where each commit becomes its own PR/MR with automatic dependency management and native stack integration where available.

The tool streamlines the development workflow by automatically creating one PR/MR per commit, managing fixups elegantly, auto-rebasing when PRs merge, and handling provider detection automatically. Key benefits include granular code reviews, cleaner git history, and support for GitHub's native stacks feature, making it ideal for developers seeking more granular, focused code review processes.
