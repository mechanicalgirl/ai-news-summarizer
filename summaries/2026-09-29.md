### Kubernetes Teams Get a Safer Way to See Their Own GPU Metrics - (InfoQ)

https://www.infoq.com/news/2026/09/kubernetes-gpu-metrics/

# Summary

Adobe engineers have developed an open-source solution that enables Kubernetes teams to safely access their own Prometheus metrics in multi-tenant environments without exposing other teams' data. The approach uses a tenant-aware proxy layered between users and a central Prometheus instance, employing NGINX, kube-rbac-proxy for authentication, and prom-label-proxy to enforce namespace constraints on queries. Teams can declare required metrics through a custom Kubernetes resource called MetricAccess, while optional per-tenant Prometheus instances can store curated metrics, significantly reducing storage overhead and creating additional isolation boundaries.

The solution addresses critical challenges in shared Kubernetes clusters, particularly for GPU-intensive workloads where teams need visibility into resource utilization and power consumption to justify expensive accelerator costs. By leveraging existing CNCF technologies rather than introducing new platforms, Adobe's architecture maintains security and performance while providing developers with self-service observability of their own metrics. This pattern is increasingly important as Kubernetes clusters become shared platforms for diverse application, data, and AI workloads.

### Atlassian Rebuilds Metrics Pipeline Around OpenTelemetry at Massive Scale - (InfoQ)

https://www.infoq.com/news/2026/09/atlassian-opentelemetry/

# Summary

Atlassian migrated its metrics pipeline from gostatsd to OpenTelemetry to handle the growing scale of data from 100,000 hosts across 14 regions while supporting traces and logs. Rather than requiring thousands of services to immediately switch to OpenTelemetry SDKs, the team maintained the existing StatsD-over-UDP interface and rebuilt the infrastructure behind it, transforming the project from an organization-wide migration into a platform-team effort. This approach involved creating purpose-built Collector distributions for collection, ingest, aggregation, and forwarding stages, with key improvements including a 30% reduction in sidecar costs, more balanced load distribution through stream ID hashing, and a 96% reduction in stored data volume through optimized aggregation.

The migration prioritized operational best practices, including gradual rollouts starting with development and staging environments, continuous production profiling to identify optimization opportunities, and preserving familiar workflows during the transition. With the core migration now complete, Atlassian plans to eventually migrate remaining application instrumentation from StatsD and vendor-specific clients to OpenTelemetry SDKs.

### Cloudflare Worker Previews: Per-Branch Environments for Workers - (InfoQ)

https://www.infoq.com/news/2026/09/cloudflare-worker-agent/

# Summary

Cloudflare has launched Worker Previews, a new feature that enables isolated, production-like environments for each Git branch of a Worker application. Each preview has its own stable URL, configuration, and state, allowing hundreds of previews to run concurrently without affecting production. The feature is designed to support agent-driven development, where coding agents generate large volumes of changes that need rapid testing and feedback loops.

The key technical innovation addresses state management through Durable Objects by creating separate namespaces and container apps for each preview, preventing production data contamination. Configuration is inherited from a base branch but can be customized per preview (e.g., pointing to staging databases instead of production). Worker Previews include scoped observability and can integrate with AI agents via browser automation for end-to-end testing. However, current limitations include incomplete isolation for multi-Worker applications, limited Queue support, and lack of staging/QA environment support.

### Python Workers Reach GA on Cloudflare, with Questions About Cold Starts and Upstream Maintenance - (InfoQ)

https://www.infoq.com/news/2026/09/cloudflare-python-workers-ga/

# Summary

Cloudflare has released Python Workers to general availability after two years of preview, enabling developers to run Python alongside JavaScript and TypeScript on its Developer Platform with integrations to various services like Workers AI, R2, and D1. The achievement required three major engineering contributions: a new packaging standard (PEP 783/PyEmscripten) for cross-compiling Python packages to WebAssembly, a socket bridge that translates POSIX system calls to the Workers connect API, and upstream contributions to HTTP client libraries to route through JavaScript's fetch API.

However, the release has sparked divided community responses. Additionally, Wasmer's founder questioned Cloudflare's cold start performance, citing benchmarks showing Python applications starting in around 900ms on Cloudflare Workers versus 60ms on Wasmer Edge, and raised concerns about version coupling to specific Python and Pyodide releases embedded in Cloudflare's infrastructure.

### Radicle Discloses Critical Flaws Exposing Private Repositories in Plain Text - (InfoQ)

https://www.infoq.com/news/2026/09/radicle-network-vulnerabilities/

# Summary

Radicle, a peer-to-peer code collaboration platform, has disclosed two critical security vulnerabilities in its core wire protocol that expose private repositories in plain text to network attackers. The flaws stem from a fundamental architectural flaw: while Radicle performs a Noise Protocol Framework handshake to establish encrypted connections, it discards the resulting encryption keys immediately after negotiation and transmits all subsequent data—including private repository contents—in cleartext over unencrypted TCP. Additionally, the authentication mechanism is flawed, allowing attackers to impersonate authorized nodes by spoofing Node IDs.

Because the existing protocol lacks version negotiation capabilities, developers cannot deploy a backward-compatible fix, forcing the project maintainers to recommend that teams immediately halt private repository operations over the public internet until a major architectural overhaul is released. As an immediate mitigation, affected organizations should treat all private repositories accessed over clearnet as compromised, rotate credentials, and isolate Radicle nodes to encrypted overlay networks like WireGuard or SSH tunnels until patched versions are available.

### Meta’s ZGateway Cuts ZippyDB Connections 19x While Handling 1B+ Operations per Second - (InfoQ)

https://www.infoq.com/news/2026/09/meta-zgateway-zippydb-proxy/

# Summary

Meta introduced ZGateway, a stateless proxy layer for ZippyDB that reduces direct database connections by approximately 19x while handling over 1 billion operations per second. The gateway addresses scalability challenges created by over one million client hosts by placing a managed proxy tier between clients and database servers, enabling clients to maintain sticky connections to regional gateway hosts rather than directly connecting to thousands of database shards across hundreds of thousands of hosts.

ZGateway provides centralized traffic management capabilities including authentication, authorization, request batching, local caching, and load balancing—tasks previously distributed across individual clients. This architectural shift reduces per-host connection counts by 97-98% and eliminates connection storms that previously caused file descriptor exhaustion and memory issues. While adding an extra network hop, this tradeoff improves overall latency by eliminating connection management overhead on database nodes, with Meta planning to eventually route all ZippyDB traffic through the gateway.

### Uber Separates Scaling Intent From Execution on Kubernetes Platform - (InfoQ)

https://www.infoq.com/news/2026/09/uber-kubernetes-scaling/

# Summary

Uber has introduced ServiceScale, a new Kubernetes controller that separates scaling intent from execution to enable multiple orchestrators to safely manage workload scaling. This solution was motivated by Uber's shift to active-active regional failovers, where the company wanted to reuse capacity from low-priority workloads instead of maintaining reserved idle capacity across all data centers. Rather than adding failover logic to their existing Uber Deployment Controller (UDC), which already handles critical service lifecycle operations, the team created a new custom resource definition (ServiceScale) and controller (SSC) that allows multiple orchestrators to express their scaling desires, which SSC then reconciles into Kubernetes objects.

The implementation keeps the system simple by storing scaling intent directly in Kubernetes rather than using external databases or coordination services, making it easier to inspect and debug. The blog post highlights three production lessons, including addressing stale informer cache issues through read-your-own-write consistency checks—a pattern that Kubernetes v1.36 has since adopted natively. This architectural approach demonstrates how Uber managed scaling complexity across its massive infrastructure of 100+ clusters and 3 million cores while maintaining system reliability and operational clarity.

### Linear Completes 1,000-PR Migration From styled-components to Meta's StyleX - (InfoQ)

https://www.infoq.com/news/2026/09/linear-stylex-meta/

# Summary

Linear, a project management tool known for its speed, has completed a major migration of its React applications from styled-components to Meta's StyleX atomic CSS-in-JS library, accomplished through over 1,000 pull requests over approximately five months. The migration was driven by performance concerns after upgrading to React 18's concurrent rendering—runtime CSS-in-JS creates performance overhead during client rendering—and the desire for better component encapsulation to prevent external restyling, which becomes increasingly important as coding agents are integrated into development workflows.

StyleX moves style generation to build time rather than runtime, resulting in significant performance gains for Linear including 20-35% less main-thread work on view-heavy pages and 30% faster navigation on mid-tier machines. Rather than migrating by hand, the team built a deterministic codemod that processed roughly 100,000 lines of code. The migration reflects a broader industry trend toward StyleX, as other companies like Cursor have similarly switched from alternative CSS solutions, with the stricter API and predictable behavior favoring automation by AI agents over the flexibility that human developers typically prefer.

### AWS Introduces Foreign Key Constraints in Aurora DSQL - (InfoQ)

https://www.infoq.com/news/2026/09/aurora-dsql-foreign-keys/

# Summary

AWS has announced that Aurora DSQL now supports foreign key constraints, addressing a critical gap that was identified as a major adoption blocker since the service's launch. The feature allows applications to enforce referential integrity directly in the database with support for CASCADE, SET NULL, and other referential actions. Aurora DSQL implements these constraints using snapshot verification during transactions and conflict detection at commit time, enabling concurrent operations without table locking.

However, the implementation comes with performance considerations that developers should be aware of. AWS notes that all DML operations on referenced or referencing tables incur additional reads, and transactions that violate constraints are rejected rather than queued, requiring applications to implement retry logic. While the community response has been largely positive—with some calling the addition a game-changer for migrations from traditional PostgreSQL—some users have raised concerns about potential performance impacts on heavily referenced rows, suggesting benchmarking before deployment.

### From Raw Data to Graph-Native AI - (Radar)

https://www.oreilly.com/radar/from-raw-data-to-graph-native-ai/

# Summary

The article argues that graph modeling—the process of transforming raw data into structured graphs—deserves equal attention alongside graph learning techniques like graph neural networks and GraphRAG. Most AI discussions focus on what to do with an existing graph, but the critical first step involves deciding what constitutes entities, relationships, timestamps, and data provenance. These foundational choices directly shape every downstream prediction and decision.

The author introduces "graph-native AI" as an approach that treats graph modeling as a first-class stage in the pipeline, where the graph becomes a shared representation supporting multiple systems (queries, predictions, retrieval, agents). Rather than assuming a single correct graph structure, the article emphasizes that different graph models—entity graphs, event graphs, or evidence graphs—serve different purposes, and the right choice depends on organizational goals. The core question shifts from "how do we learn from this graph?" to "what should the graph be in the first place?"

### Human Judgment Doesn’t Leave the Software Factory, It Relocates - (Radar)

https://www.oreilly.com/radar/human-judgment-doesnt-leave-the-software-factory-it-relocates/

# Summary

The article argues that while software factories automate code generation and development workflows, **human judgment remains essential—it simply relocates rather than disappears**. The author, Addy Osmani, emphasizes that humans must stay involved in critical decisions upfront (product intent, system design, quality standards) and maintain oversight through intentional code review and quality gates, rather than trying to fully automate the software development process.

The piece provides practical guidance for building effective software factories: implement continuous quality checks (type systems, tests, security scanners) as early as possible, focus on signal-to-noise ratio rather than quantity of checks, and maintain human ownership of what ships to production. Osmani suggests that for many use cases, traditional coding tools may suffice, and a factory is only necessary when workflows need to be repeatable and event-driven—with humans ultimately deciding what becomes ready to merge and what ships to users.
