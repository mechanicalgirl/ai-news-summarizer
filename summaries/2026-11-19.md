### NetWasm 0.10 Speeds Up C# on WebAssembly, Now Faster Than Mono AOT - (InfoQ)

https://www.infoq.com/news/2026/11/NetWasm-0-10-Faster/

# Summary

NetWasm 0.10 has significantly improved C# performance on WebAssembly, now outperforming Mono AOT across most benchmarks. The compiler, which translates C# into standalone WebAssembly files, achieved these gains through optimizations spanning versions 0.10.1 to 0.10.8, including improved exception handling, array bounds check elimination, SIMD support, and optimized integer division. On the project's benchmark suite, NetWasm 0.10.8 runs at approximately 0.41 times Mono AOT's execution time (a geometric mean) and achieves 0.87 times desktop .NET's speed, representing substantial improvements from earlier versions.

The optimizations targeted specific performance bottlenecks: exception handling reduced overhead from register save-restore operations, inlining of small methods and loop-invariant hoisting improved throughput, and SIMD vectorization delivered dramatic speedups for compute-heavy workloads like solving partial differential equations. While some gaps remain—particularly with vector operations and certain math functions—NetWasm has established itself as a competitive option for running .NET applications in WebAssembly environments.

### LinkedIn Cuts Daily Spark Shuffle Fetch Failures from 750 to 20 with Apache Celeborn - (InfoQ)

https://www.infoq.com/news/2026/11/linkedin-celeborn-remote-shuffle/

# Summary

LinkedIn deployed Apache Celeborn, a shared remote shuffle platform, to handle intermediate data storage for its Apache Spark and Apache Flink workloads, achieving dramatic improvements in reliability and performance. By separating shuffle storage into dedicated workers rather than keeping it within compute clusters, LinkedIn reduced daily shuffle fetch failures from approximately 750 to 20, lowered compute costs by 10%, and improved application runtimes by 14% compared to its previous Magnet implementation.

The deployment involved substantial engineering work, including a five-node Raft-based control plane with network-aware replication, integration with health monitoring systems, and optimization through NVMe SSD storage and Zstandard compression. These enhancements reduced shuffle cost per task by nearly 90% and executor wait times by 10-15%, while enabling LinkedIn's transition to a unified Flink architecture that completes multi-day historical workloads in single-digit hours.

### Vercel Releases UI SDK for Agents to Compose UI from Reusable Behaviors - (InfoQ)

https://www.infoq.com/news/2026/11/vercel-ui-sdk/

# Summary

Vercel has released UI SDK, an open-source TypeScript library that decomposes UI functionality into over 50 reusable behaviors (such as keyboard navigation, focus management, and drag-and-drop) rather than embedding them in finished components. Developers or AI agents combine these behaviors using a `definePrimitive` function, which can then be rendered across multiple frameworks (React, Vue, Svelte, Solid, Web Components) through consistent part names and unstyled components.

A key distinguishing feature is UI SDK's first-class support for AI agents: it provides an agent bridge (`createAgent`) that allows agents to read component state and trigger actions without screenshots, while apps can approve or refuse agent-initiated changes. Currently in beta, UI SDK sits at a lower architectural level than existing headless libraries like Radix UI and Base UI, focusing on composable, framework-agnostic behaviors with native agent integration capabilities.

### AWS PrivateLink Tunnel Endpoints Open a Whole CIDR Range to Another Account - (InfoQ)

https://www.infoq.com/news/2026/11/aws-privatelink-tunnel-endpoints/

# Summary

AWS has launched tunnel endpoints, a new VPC endpoint type that allows applications in one AWS account to access an entire CIDR range in another account, rather than requiring separate configurations per resource. The provider shares a CIDR-type resource configuration through AWS Resource Access Manager, and the consumer creates a tunnel endpoint against it, gaining access to all current and future resources within that address range. This solves vendor-access problems where service providers need to reach customer resources without full VPC peering access, while maintaining security through address range restrictions and one-directional connectivity.

The technical implementation requires consumer applications to send traffic wrapped in GENEVE encapsulation protocol over UDP port 6081 to the tunnel endpoint, which then unwraps and routes the traffic within the provider VPC. While this offers advantages over VPC peering (which is bidirectional and exposes the entire VPC) and VPC Lattice (which operates at layer 7), tunnel endpoints have notable constraints including support for TCP only (DNS UDP exceptions), no support for ICMP, and limited logging capabilities that cannot track individual workloads behind a vendor endpoint.

### Yelp Migrates Cassandra to EKS by Moving EBS Volumes - (InfoQ)

https://www.infoq.com/news/2026/11/kubernetes-cassandra-eks/

# Summary

Yelp successfully migrated its Cassandra fleet from legacy self-managed Kubernetes clusters to Amazon EKS without downtime or data loss by developing a "Rolling PV Transplant" technique. Rather than streaming data between nodes—which would have taken weeks for large clusters—the team leveraged the fact that EBS volumes are pinned to Availability Zones independent of Kubernetes clusters. They pre-created PersistentVolumes in EKS referencing existing volume IDs, then systematically moved pods one at a time by deleting legacy cluster pods, waiting for volume detachment, and allowing EKS pods to claim the same volumes with their data intact. This approach moved approximately 1,000 TiB across roughly 1,000 pods by pointer rather than over the network.

The migration covered about 90 production clusters with minimal operational overhead—one engineer completed the production rollout in three weeks, migrating three to six clusters per day. The technique leveraged Cassandra's replication tolerance for brief node downtime and included a rollback mechanism for the few instances where issues arose. Beyond technical execution, Yelp emphasized the importance of auditing repair state, backup IAM roles, and alert severity before migration. The approach is applicable to any AZ-pinned stateful workload on Kubernetes and has since been used for Kafka clusters as well.

### Qwik 2.0 RC: Replaces HTML Comment Markers for Faster Reactivity and Out-of-Order Streaming - (InfoQ)

https://www.infoq.com/news/2026/11/quik-2-streaming/

# Qwik 2.0 RC Summary

Qwik, a resumable JavaScript framework, has released version 2.0 Release Candidate with significant architectural improvements. The major change replaces HTML comment markers (like `<!--qv-->`) used in v1 to track component state with compressed `<script>` blocks, eliminating the need for ordered HTML writes and reducing JavaScript overhead from 59KB to 9KB before interactivity. Performance benchmarks show v2 is 1.23x slower than vanilla JavaScript, outperforming Vue 3.5, Angular, and React 19 with the compiler.

The RC introduces experimental out-of-order streaming capabilities through `<Pending>` and `<Catch>` boundaries, allowing servers to send complete pages immediately while streaming slow content later. Additional features include async support in `useComputed$`, route loader JSON endpoints with caching, Web Worker primitives, and HMR that preserves state across edits. The team notes breaking changes are minimal and automated through migration tools, with the RC available for exploration via the online playground.

# Summary

# Summary

As AI increasingly handles coding tasks, programmers must shift their focus to higher-level responsibilities, particularly in specification writing and code repair. This shift requires developers to master communication skills, critical thinking about edge cases, and the ability to guide AI tools rather than hands-on coding expertise.
