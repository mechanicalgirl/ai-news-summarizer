### PEP 814: Add frozendict built-in type - (Python Weekly)

https://vstinner.github.io/pep-814-add-frozendict-builtin-type.html

# Summary

PEP 814 introduces a new `frozendict` built-in type to Python 3.15—an immutable, hashable dictionary implemented in C by Victor Stinner and Donghee Na. Unlike the existing `types.MappingProxyType`, `frozendict` is hashable if all its values are hashable, preserves insertion order, and shares most of its implementation with the standard `dict` type (only ~7% of code is frozendict-specific). The proposal drew inspiration from earlier PEP 416 (rejected in 2012) and PEP 603's `frozenmap`, but offers a simpler approach aligned with dict's familiar API.

The implementation has been integrated into the Python standard library across multiple modules including `json`, `pickle`, `dataclasses`, and others. Various optimizations were made for Free Threading, hash computation, and memory management, while handling edge cases like recursive frozendicts and garbage collection visibility. However, widespread conversion of stdlib dictionaries to frozendict was limited after the Steering Council requested module-maintainer approval for each change, and concerns arose about backward compatibility with projects like Cinder.

### You shouldn't trust Trusted Publishing - (Python Weekly)

https://blog.yossarian.net/2026/07/07/You-shouldnt-trust-trusted-publishing

# Summary

Trusted Publishing is a machine-to-machine authentication scheme adopted by PyPI and other package registries that uses short-lived credentials tied to CI/CD machine identities instead of long-lived API tokens. The article clarifies a critical misconception: the "trust" in Trusted Publishing refers only to the authentication relationship between external machine identities and package indexes—it is *not* a signal of package safety, quality, or trustworthiness for human users. Because PyPI is publicly accessible, anyone can use Trusted Publishing to upload anything, including malware, making it functionally equivalent to API tokens in terms of what it authenticates.

PyPI deliberately avoids presenting Trusted Publishing status as a trust indicator by refusing to display it prominently (no "green checkmark"), instead rendering it as an obscure boolean deep in file metadata. The article emphasizes that Trusted Publishing is purely an authentication mechanism—all it proves is that an upload was authenticated. Users seeking to evaluate package safety cannot and should not rely on Trusted Publishing status, as it provides no information beyond confirming that a credential was properly validated during upload.

### Sandboxing an AI Agent - (Python Weekly)

https://sajalsharma.com/posts/sandboxing-an-ai-agent/

# Summary

This article explores sandboxing as a security and operational solution for AI agents that autonomously write and execute code. As agents gain long-horizon autonomy and run without constant human approval, they pose security risks—potentially accessing private data, processing untrusted content, and exfiltrating information. A sandbox is an isolated, ephemeral environment with its own filesystem, processes, and hard resource limits that isolates agent code execution and can be deleted after each run, protecting the host system.

The article identifies five key benefits of sandboxing: containment (preventing agents from harming real systems), parallelism (allowing multiple agents to run simultaneously without interfering), reproducibility (starting fresh from a consistent image each run), resource governance (preventing runaway processes), and cheap recovery (quickly discarding and restarting failed runs). It then compares two architectural approaches: the sandbox-as-tool-backend (where the agent loop runs locally and only delegates code execution remotely) and the agent-in-the-box model (where the entire agent runs within the sandbox). Each approach involves tradeoffs regarding API key security, file transfers, and latency.

### Hamiltonian Neural Networks from a Differential Geometry Perspective - (Python Weekly)

https://abscondita.com/blog/symplectic-sledgehammer-for-a-spring

# Summary

This article explores Hamiltonian Neural Networks through the lens of differential geometry, arguing that machine learning models can be made more physically accurate by building conservation laws into their architectural structure rather than relying on massive parameter counts and hyperparameter tuning. The authors use a simple mass-spring system as their example, demonstrating how naive neural networks fail to preserve energy over time—causing simulated orbits to spiral instead of maintaining closed loops—because their architecture has no inherent reason to enforce conservation laws.

The article promises to explain why this failure occurs and how to fix it using symplectic geometry, presenting the solution three equivalent ways: through geometry, learning theory, and symmetry principles. Rather than treating phase space as a simple 2D plane, the authors carefully develop the mathematical machinery (symplectic forms, differential forms, manifolds) to show that the shape and structure of what a neural network is allowed to learn can enforce conservation laws without explicit instruction, making the model fundamentally more aligned with the underlying physics.

### Celery on AWS ECS - Complete Guide - (Python Weekly)

https://jangiacomelli.com/blog/celery-on-aws-ecs/

# Summary

This article provides a comprehensive guide to running Celery task queues on AWS ECS, identifying common pitfalls and their solutions. The main problems discussed include tasks being lost during ECS interruptions (due to SIGTERM/SIGKILL), tasks never completing if they exceed deployment windows, unnecessary task delays from prefetching, soft-timeout failures, and duplicate task processing. These issues stem from Celery's default configurations that aren't optimized for ECS environments.

The article recommends solutions including using RabbitMQ (via Amazon MQ), configuring critical Celery settings like `task_acks_late=True`, `task_reject_on_worker_lost=True`, and `worker_prefetch_multiplier=1`, implementing exponential retries with short visibility timeouts, and designing tasks to be fast and interruptible. It also suggests architectural patterns like "fan out" (splitting work into small tasks) and batching to ensure tasks complete within the 120-second ECS grace period before forced termination.

### Miles: A PyTorch-Native Stack for Large-Scale LLM RL Post-Training - (Python Weekly)

https://pytorch.org/blog/miles-a-pytorch-native-stack-for-large-scale-llm-rl-post-training/

# Summary

Miles is an open-source reinforcement learning framework developed by RadixArk for large-scale LLM post-training, built natively on PyTorch and designed to handle the distributed systems complexity of modern RL training. It integrates SGLang for high-throughput sample generation, Megatron-LM for scalable distributed training, and Ray for cluster orchestration, following a philosophy of a small, customizable core surrounded by pluggable components that teams can modify for new algorithms without forking the framework.

The framework addresses key challenges in frontier-scale LLM RL, including coordinating rollout and training across distributed hardware, maintaining policy synchronization, handling mixture-of-experts routing consistency, and ensuring fault tolerance in week-long workloads. By keeping PyTorch as the common programming layer throughout the stack and exposing well-defined extension points, Miles makes LLM RL more composable, reproducible, and easier to scale while remaining accessible for customization by researchers and infrastructure teams.

# Summary
