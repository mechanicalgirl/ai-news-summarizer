### Python: how time-machine is O(1) where freezegun is O(n) - (Python Weekly)

https://adamj.eu/tech/2026/08/03/python-time-machine-o1-freezegun-on/

# Summary

The article compares `time-machine` and `freezegun`, two Python libraries for mocking date/time in tests. Through benchmarking, it demonstrates that `time-machine` operates in O(1) constant time while `freezegun` operates in O(n) linear time relative to the number of loaded modules. On a project with 16,000 modules, `time-machine` completes in 1.5 microseconds while `freezegun` takes 41 milliseconds—a 27,300x difference that grows worse as projects scale.

`Freezegun` is slow because it iterates through every loaded module in `sys.modules` searching for copies of datetime/time functions that other modules imported, then replaces each one with fake versions. This sweep must happen every time time is frozen. In contrast, `time-machine` achieves constant time by directly modifying the C function pointers in CPython's built-in `time.time` and `datetime` objects at a low level, bypassing the need to search modules. This fundamental architectural difference explains why `time-machine` maintains near-instant performance regardless of project size, while `freezegun`'s cost scales linearly with the number of module attributes.

### Setting Django's DEBUG safely - (Python Weekly)

https://lincolnloop.com/blog/setting-djangos-debug-safely/

# Summary

Django's DEBUG setting should never be enabled in production environments, despite being the default for local development. When DEBUG=True, Django exposes critical security vulnerabilities including detailed stack traces, configuration details, and sensitive environment information to attackers. Additionally, it degrades performance through non-minified static files, increased database query logging, and excessive memory usage, while disabling error notifications to administrators.

To prevent accidentally deploying with DEBUG=True, developers should default all security-related settings to production-ready values (DEBUG=False) and only override them for local development. When setting DEBUG via environment variables, proper boolean parsing is essential—using utilities like django-environ or a custom parsing function—since naive string comparisons can accidentally evaluate "false" or "0" as True.

### Categorization with NLP - (Python Weekly)

https://softwaremaniacs.org/blog/2026/07/30/categorization-with-nlp/en/

# Summary

Ivan Sagalaev describes his NLP-based categorization algorithm for a grocery shopping app that automatically assigns products to categories (dairy, produce, beverages, etc.). Rather than using machine learning due to insufficient training data, he built a rule-based system that normalizes product names into stemmed words, then matches them against a CSV database organized by significance levels. The system uses unigrams (single words) and bigrams (word pairs) to handle both simple cases like "milk" and complex cases like "apple sauce," with derivations (like "juice") prioritized over raw ingredients.

To handle real-world complications, Sagalaev added syllable splitting for compound words like "redbull" that people often misspell, and implemented spell-checking using Damerau-Levenshtein edit distance against his own database rather than standard dictionaries (since international foods and brand names don't fit conventional spelling rules). He also included various optimizations like assuming correct first letters and exact match prioritization, while leveraging his small dataset size as a performance advantage.

### Wheels, Bottles and Images - (Python Weekly)

https://nesbitt.io/2026/07/30/wheels-bottles-images.html

# Summary

This article examines three major binary distribution systems—Python wheels, Homebrew bottles, and OCI container images—revealing surprising architectural similarities despite being designed independently. All three distribute checksummed, immutable artifacts selected by platform tags (CPU architecture, OS, ABI), downloaded over plain HTTP from separate index and storage systems. Key differences include their dependency models: wheels and bottles resolve dependencies at install time, while images carry everything needed above the kernel. The systems are converging, with Homebrew now storing bottles in OCI registries since 2021 and all three adopting sigstore bundles for build attestations.

The article argues that designing a new binary distribution system today requires less work than historically invested in wheels, since OCI registries provide the infrastructure foundation and gem2 specifies platform tag dimensions. The main remaining design decisions involve tag grammar and index format. However, an unresolved challenge across all three systems is handling specialized hardware like GPUs—current platform tag specifications don't account for these dimensions, leading to incompatibilities like CUDA wheels being excluded from PyPI. Cross-ecosystem standardization efforts like PURL's platform qualifiers remain incomplete.
