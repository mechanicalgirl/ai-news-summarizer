### Soft delete in Django without making a mess - (Python Weekly)

https://codewithstein.com/django-soft-delete/

# Summary

This article explains how to implement soft deletes in Django properly by marking records as deleted (using a `deleted_at` timestamp) rather than physically removing them. The key challenges addressed include: keeping deleted rows hidden from normal queries through custom managers and querysets, preventing accidental bulk deletes, handling unique constraint violations when restoring deleted records, and using conditional unique constraints (database-dependent) to allow deleted rows to release their unique field values.

The solution involves creating a reusable abstract `SoftDeleteModel` base class with two managers (`objects` for active records, `all_objects` for all records), custom queryset methods that override `delete()` to soft-delete and require explicit `hard_delete()` calls for permanent removal, and conditional unique constraints to make uniqueness apply only to active rows. This approach keeps the behavior explicit in code while preventing common pitfalls like accidental data loss and unique constraint conflicts during restore operations.

### Breaking the AWS MCP Python Sandbox - (Python Weekly)

https://xplo1t-sec.github.io/posts/breaking-the-aws-mcp-python-sandbox/

# Summary

This article describes a critical vulnerability in AWS's MCP (Model Context Protocol) Python sandbox that allowed users to execute arbitrary system commands. The researcher discovered that the sandbox's AST validator and runtime protections failed to account for Python 3.10's structural pattern matching (match/case statements). By manipulating the `__match_args__` attribute of namedtuple classes, they could perform hidden attribute reads that bypassed the sandbox's restrictions on accessing sensitive dunder attributes like `__class__` and `__globals__`.

The attacker chain involved: (1) using `collections.namedtuple()` to create a class with controllable `__match_args__`, (2) reading the `__reduce_ex__` method through pattern matching to access `copyreg.__newobj__`, (3) retrieving the original `__builtins__` dictionary through the function's `__globals__`, and (4) using the unprotected `__import__` builtin to load `os` and `subprocess` modules for command execution. This vulnerability allowed complete compromise of the Lambda sandbox environment where user-supplied Python scripts were intended to run securely.

### UUIDv7 doesn't have the properties you think it does - (Python Weekly)

https://alexsci.com/blog/uuidv7-is-weird/

# Summary

UUIDv7 is commonly promoted as providing monotonically increasing IDs with accurate creation timestamps and unguessability, but RFC-compliant implementations often fail to deliver these properties reliably. The embedded timestamp may not reflect actual object creation time since implementations are allowed to alter timestamps to maintain monotonicity—particularly when generation rates exceed counter capacity or system clocks jump backwards. Additionally, no widely-used implementations persist timestamps to storage, causing out-of-order IDs after process restarts following clock adjustments.

The only property UUIDv7 reliably guarantees is uniqueness and collision resistance. While roughly-ordered IDs remain useful for many applications, users should carefully evaluate their specific implementation's actual guarantees rather than assuming standard benefits. When selecting a UUIDv7 implementation, critical questions include: what additional properties beyond uniqueness it guarantees, under what conditions those properties hold, and how the implementation handles clock synchronization issues and backwards jumps.

### Loading 33,000 Peaks on Demand with a z10 Tile Grid - (Python Weekly)

https://peter-hoffmann.com/2026/loading-peaks-on-demand-with-a-z10-tile-grid.html

# Summary

Peter Hoffmann describes how biwak.info efficiently displays 33,437 Alpine peaks on a Leaflet map without requiring users to download a massive 15.4 MB file. The solution divides peaks into files using the same z10 tile grid that Leaflet maps use—the same coordinate-to-tile formula works on both the server (Python build) and client (JavaScript), ensuring peaks are always stored in the correct file. Each tile represents approximately 27×27 km and contains a median of 93 peaks as compact JSON files (13 KB median, 3.6 KB gzipped), allowing the browser to fetch only the tiles visible in the current view.

The implementation includes intelligent optimizations: peaks are ranked by prominence to show only significant summits at lower zoom levels, a manifest file prevents unnecessary 404 requests, an LRU cache limits memory usage, and a single canvas layer draws all peaks efficiently rather than using thousands of markers. The client automatically computes which tiles are needed based on the current view and a 25% margin, fetching them on-demand with controlled parallelism. This elegant approach requires no database or server and creates stable deep-links for individual peaks using the same tile-coordinate mathematics.

### Stop Django Bulk Operations From Silently Skipping Signals - (Python Weekly)

https://johnnymetz.com/posts/django-bulk-operations-skip-signals/

# Summary

Django's bulk operations (`bulk_create()`, `bulk_update()`, and `update()`) skip Django signals like `pre_save` and `post_save` for performance reasons, but do so silently. This creates a "footgun" where critical side effects—such as cache invalidation, audit logging, or search index updates—fail without warning or error. For example, bulk-updating book titles won't trigger a search index update, leaving stale results in the search system.

The article proposes a solution: create a custom `SignalSafeQuerySet` that overrides these three methods to raise a `RuntimeError` unless explicitly bypassed. Developers can wrap necessary bulk operations in an `allow_signal_skipping()` context manager for performance-critical tasks. This makes signal-skipping explicit and searchable in code reviews. The solution also covers edge cases like reverse foreign key operations and async variants, though it doesn't address raw SQL or data migrations, which would require database-level triggers for complete coverage.

### The Shift of Theseus — Toy Bit Provenance Abstract Domain - (Python Weekly)

https://pypy.org/posts/2026/10/toy-bit-provenance.html

# Summary

This article describes a "bit provenance" abstract domain for optimizing bit manipulation operations in the PyPy compiler. Unlike simpler bit-tracking approaches, this domain tracks not just whether individual bits are 0, 1, or unknown, but also **where bits come from** — allowing it to recognize when a bit in one variable is identical to a bit in another variable at a different position. This enables optimizations like recognizing that `result = a & c` equals `a` when `a` and `c` compute the same value through different bit shift operations.

The article explains the implementation of this domain using data structures like `SourceBit` (which references a specific bit of an SSA operation) and `BitProvenance` (which stores the provenance information for all 64 bits of a value). It then details how to implement transfer functions for various operations — starting with simple ones like bitwise invert and shifts with constant amounts — demonstrating how each operation propagates or transforms bit provenance information through the computation.

### tar-codec: a fast and secure tar parser for the Rust ecosystem - (Python Weekly)

https://astral.sh/blog/tar-codec

# Summary

**tar-codec** is a new tar parser that Astral developed for uv (a Python package installer) to replace the older astral-tokio-tar implementation. Starting with version 0.13, uv uses tar-codec to parse source distributions, achieving roughly twice the performance while reducing security risks. The shift was motivated by security concerns: researchers discovered multiple "parser differentials" in the previous implementation that could cause different tools (uv, pip, etc.) to extract different contents from the same tarball, potentially allowing attackers to create archives that appear safe to package indices but extract dangerously when parsed by installers.

The article provides extensive background on the tar format itself, explaining that tar is fundamentally a block-based format evolved from tape archival technology with three main variants (UNIX V7, UStar/pax, and GNU tar), each with different limitations and capabilities. The tar format's inherent ambiguities—such as allowing arbitrary data in padding spaces rather than enforcing strict standards—make it particularly prone to parser differentials. Astral concluded that retrofitting security constraints into the existing tokio-tar codebase would be impractical, leading them to build tar-codec from scratch to systematically understand the format, eliminate differentials, and achieve better performance.

### The State of Context Engineering - (Python Weekly)

https://www.dbreunig.com/2026/10/24/the-state-of-context-engineering.html

# Summary

Context engineering—the practice of effectively instructing AI models—has emerged as a permanent challenge in AI development, despite efforts to solve it through ever-larger context windows. While late 2024 saw optimism that million-token context windows would eliminate the need for selective information curation, this approach created new problems. The author identifies four key failure modes: context poisoning (bad information the model can't escape), context distraction (models favoring examples over instructions as context grows), context confusion (irrelevant facts influencing responses unexpectedly), and context clash (conflicting tools and information within systems).

To manage these challenges, engineers have developed six core tools: context augmentation (RAG and skills), tool loadout (selective tool exposure), context quarantine (isolated subagents), context pruning (removing unnecessary data), context offloading (storing information externally), and context summarization (compaction). The key insight is that context engineering will remain difficult regardless of model improvements, but in uniquely solvable ways—the job requires knowing when to be deterministic and when to be probabilistic in how information is presented to AI systems.

### Custom Voices With Qwen3-TTS - (Armin Ronacher's Thoughts and Writings)

https://lucumr.pocoo.org/2026/10/29/qwen3-custom-voices/

# Summary

Armin Ronacher explores using Qwen3-TTS for custom voice narration in a game project with his children. He compares three Qwen3 models—Base (voice cloning), CustomVoice (built-in speakers with instructions), and VoiceDesign (voice generation from text descriptions)—and discovers that while Base can clone voices, it lacks instruction capabilities. To work around this limitation, he develops a clever workaround by extracting voice embeddings from Base and feeding them into CustomVoice to enable instruction-based cloning with custom voices.

Beyond basic voice cloning, Ronacher experiments with voice embeddings as mathematical vectors, demonstrating how to blend two voices together, use embeddings for speaker detection, and manipulate voice characteristics like gender by performing arithmetic operations on the embedding space. While blending works reasonably well and gender manipulation is possible, he notes that cloned voices respond less reliably to instructions than built-in speakers. Overall, he concludes the approach is practical for creating unique AI-generated voice-overs.
