### Stricter checks for uploaded distributions on PyPI - (Python Weekly)

https://blog.pypi.org/posts/2026-11-18-stricter-checks-for-uploaded-sdists/

# Summary

PyPI has implemented stricter validation checks for uploaded Python package distributions to combat security vulnerabilities arising from parser differentials—situations where different tools parse the same archive file differently, potentially allowing malicious code to bypass detection. The initial changes reject source distributions using legacy V7-style tar archives and built distributions with potentially misinterpreted ZIP comments. These stricter standards conform to official packaging specifications and aim to ensure consistency across PyPI, mirrors, security scanners, and installation tools.

For end users, these changes have no impact as existing packages will continue to work. Package maintainers are largely unaffected since most distributions already comply with standards, but those receiving upload rejections should use modern Python build backends that automatically produce compliant archives, or manually ensure their distributions use POSIX pax-style tar archives and proper UTF-8 encoding. PyPI plans to continue tightening restrictions on archive formats in the future while prioritizing minimal disruption to the ecosystem.

### PyPI code that breaks on Python 3.12 and 3.13 - (Python Weekly)

https://py-code.org/blog/removed-stdlib-modules-pypi/

# Summary

Python 3.12 and 3.13 removed 25 standard library modules (including distutils, imp, cgi, and others), breaking code that imports them. A comprehensive scan of PyPI found that 3,763 projects (1.1%) import these removed modules, with 1,623 projects having unguarded imports that would actually fail. Among the 60,000 most-downloaded projects, 852 have problematic unguarded imports, and notably, 544 of these haven't had a release in two years yet still receive 126 million downloads monthly.

The most impactful failures involve widely-used but outdated packages: nose and boto alone receive 5.2 million downloads per month despite failing on Python 3.12 and later (last released in 2015 and 2018 respectively). Other notable failures include coreapi, htmlmin, and pydub on Python 3.13. The analysis reveals that most problematic imports are concentrated in unmaintained projects, though temporary fixes exist—like installing setuptools for distutils compatibility or adding PyPI backports (legacy-cgi, audioop-lts, etc.) as dependencies.

### Faster CI with Orchestrated Pytest Workers - (Python Weekly)

https://making.close.com/posts/faster-ci-with-orchestrated-pytest-workers/

# Summary

Close's backend has nearly 58,000 integration tests that run in under 2.5 minutes through an orchestrated pytest worker system. After 12 years of incremental optimizations using traditional test splitting (which parallelizes tests deterministically across machines), the team hit a performance wall around 12 minutes due to fixed-cost setup steps like database startup and test collection that couldn't scale with increased parallelization.

To overcome this bottleneck, Close adopted a centralized orchestration architecture inspired by Playwright testing tools. An orchestrator server coordinates test distribution dynamically across workers rather than splitting tests deterministically, allowing setup steps to run in parallel with test collection. This architecture also enables cost-effective use of AWS spot instances—replacing 17 on-demand runners with just 2 on-demand runners plus 54 spot instances at similar cost—achieving their target CI speed.

### funkycache: a Python library to cache functions in SQLite - (Python Weekly)

https://alexwlchan.net/2026/funkycache/

# Summary

**funkycache** is a Python library that provides intelligent caching for functions using SQLite as a backend. The author created it to speed up their static site generator by caching deterministic functions with no side effects. Unlike basic key-value caching, funkycache uses a decorator pattern similar to `functools.cache`, automatically handling cache logic including serialization of arbitrary Python objects, function argument hashing, and cache invalidation based on source code changes.

The library implements several sophisticated features to optimize performance and reliability: it uses the `inspect` module to normalize function arguments regardless of calling style, serializes data to JSON for flexibility and debugging, and uses XXH64 hashing for efficient SQLite key storage. It also supports dependency tracking on external files and library versions to automatically invalidate cached results when dependencies change, and includes special handling for lazy generators by materializing them into lists with memory budgets. The library is designed so users can employ it without understanding its internal mechanics, though the article provides detailed technical explanations of its implementation.

### What makes uv slow? - (Python Weekly)

https://blog.schuetze.link/what-makes-uv-slow/

# Summary

This article explores the factors that make uv (a Python package manager) slow, despite its reputation for speed. The author explains that uv's performance comes from systematic optimization rather than shortcuts, following a hierarchy of improvements: eliminating external tool invocations, reducing network requests, optimizing CPU-heavy operations (compression, hashing, parsing), minimizing disk I/O, and improving concurrency and memory management. The article provides benchmarks across different scenarios (Jupyter, Airflow, Boto3, Home Assistant, Plotly) showing performance on various systems, and identifies specific bottlenecks including TOML parsing overhead (taking ~30ms for large projects), workspace metadata checking, and network concurrency limitations.

The author demonstrates that while uv excels at package installation and resolution, slowdowns occur in areas like parsing configuration files, checking dependency freshness in large workspaces, and backtracking through complex version constraints. Performance varies significantly based on hardware (desktop vs. Raspberry Pi vs. Windows laptop) and cache state, with cold cache installations taking considerably longer than warm cache operations. The article emphasizes that optimization priorities focus on high-level operations first—like eliminating repeated builds—before addressing low-level concerns like memory allocation.

### Understanding Positional Embeddings in Modern LLMs - (Python Weekly)

https://magazine.sebastianraschka.com/p/understanding-positional-embeddings

# Summary

This article provides a comprehensive guide to positional embeddings in Large Language Models (LLMs), explaining how models encode and process token position information. It covers classic methods like learned absolute embeddings used in GPT-2, contemporary approaches like RoPE (Rotary Position Embedding), and how modern architectures handle or omit explicit positional encodings. The author uses visual examples, mathematics, and PyTorch implementations to explain why positional information is necessary—since identical tokens appearing in different positions would otherwise receive identical embeddings, making it impossible for the model to distinguish word order and meaning.

The article begins by establishing that position information is critical because changing word order changes sentence meaning (e.g., "The red fox jumps" vs. "The gray fox jumps"). It then walks through how GPT-2 adds learned position vectors directly to token embeddings before passing them to transformer blocks, contrasting this with how modern LLMs like MiniMax-M3 integrate positional information within attention mechanisms using methods like RoPE. The piece is technical and assumes familiarity with LLM architectures, serving as both a standalone tutorial and foundation for future discussions on LLM architecture trends.

### Adapting CPython for yk - (Python Weekly)

### How to find and fix N+1 queries in Django - (Python Weekly)

https://codewithstein.com/fix-n-plus-one-queries-django/

# Summary

N+1 queries are a common Django performance problem where a single initial query to fetch objects is followed by additional queries for each object's related data. The article demonstrates this issue using an article listing page with ForeignKey relationships (author, category) and a ManyToManyField (tags)—resulting in 61 total queries for just 20 articles. The solution involves using Django's `select_related()` for one-to-one relationships and `prefetch_related()` for many-to-many or reverse relationships, which reduce the query count to just 2 by batching related object fetches.

The article emphasizes profiling queries with Django Debug Toolbar before optimizing, and recommends using `select_related()` when one object points to a single related object (ForeignKey, OneToOneField) versus `prefetch_related()` for relationships where one object can have multiple related objects (ManyToMany, reverse ForeignKeys). Both can be combined in a single queryset for comprehensive optimization without changing the template logic.

### Microsoft agent-framework Compromised Twice on PyPI - (Python Weekly)

https://safedep.io/blog/microsoft-agent-framework-pypi-compromise

# Summary

Two malicious releases of Microsoft's agent-framework Python package (versions 1.26.1 and 1.26.2) were published to PyPI on November 17, 2026, designed to steal credentials and tokens from any environment where they were installed. The malware used a .pth file that executed automatically whenever Python started, allowing it to harvest environment variables, credential files, and request fresh tokens from Azure DevOps, Azure managed identity, and GitHub Actions without requiring the package to be explicitly imported. SafeDep detected both compromised versions within minutes of upload (22 and 4 minutes respectively), but not before an attacker with a newly created account called "vibiret" published a second malicious version after the first was removed from PyPI.

The attack exposed a significant supply chain vulnerability, as the attacker gained maintainer access to agent-framework and five related projects on the same day of the compromise, with no cryptographic way for users to distinguish the malicious releases from legitimate Microsoft uploads since PyPI lacked provenance attestation. With approximately 192,000 monthly downloads, the actual number of compromised installations remains unknown, and the attacker retained access to multiple projects as of the article's publication date.

### zar-rs - (Python Weekly)

https://brmmm3.github.io/posts/2026/11/15/zar-rs/

# Summary

ZAR is a new archive format implemented in Rust with a native Python API (pyzarlib) that offers significant performance improvements over traditional formats like ZIP and tar.gz. Unlike conventional archives, ZAR is designed to manage file changes over time through a commit-based system, allowing users to preserve earlier versions, perform deduplication, enable random file access, and restore individual files without unpacking everything. The format uses parallel Zstandard compression with block-based framing, achieving speeds that compress a 525 MiB Linux source tree in 0.86 seconds—compared to 11.01 seconds for ZIP and 24.91 seconds for 7z—while producing smaller archives than ZIP (though larger than 7z).

The Python package provides an intuitive API for creating, updating, inspecting, and extracting archives with support for custom metadata, encryption with per-commit passwords, and import from multiple archive formats. Beyond Python, the same Rust library powers command-line tools, a desktop application, and bindings for numerous languages (Go, Java, C#, WebAssembly, and more). ZAR is ideal for developers seeking a balance between compression speed and archive size while maintaining useful historical snapshots and comprehensive archive management capabilities.
