### DoorDash Uses Envoy and Valkey for a 1.5M RPS Proxy Cache with 99.99999% Availability - (InfoQ)

https://www.infoq.com/news/2026/07/doordash-entity-cache-proxy/

# Summary

DoorDash has developed Entity Cache, a transparent proxy caching platform built on Envoy and Valkey that reduces redundant service-to-service requests across its microservices architecture. The platform operates within the service mesh layer, intercepting HTTP and gRPC requests to cache frequently accessed but infrequently changing data without requiring application code changes. It currently supports over 100 endpoints across 50 services, handling 1.5 million requests per second with 99.99999% availability.

The platform combines several sophisticated features including Kafka-based event-driven cache invalidation, dual TTL thresholds for resilience during outages, and performance optimizations such as lock-free single-flight mechanisms and probabilistic early refresh algorithms. These optimizations have delivered significant improvements: 50-60% reduction in memory allocation rates, five-fold increase in throughput per pod, up to 80% reduction in P99 latency spikes, and cache hit rates exceeding 90%, while reducing upstream requests by 60-95%.

### Podcast: Strands Agents with Clare Liguori - (InfoQ)

https://www.infoq.com/podcasts/strands-agents/

# Summary

Clare Liguori, technical lead of the open-source Strands Agents SDK, discusses how the framework evolved from an internal AWS project to a production-ready system. Strands was created to address the complexity and brittleness of existing agent frameworks by adopting a model-driven architecture that simplifies agent development to just three components: a system prompt, a set of tools, and a choice of model.

The key innovation is Strands' "model-driven approach," which relies on modern LLMs' improved reasoning and tool-calling capabilities rather than rigid, workflow-based scaffolding. The framework incorporates "Steering"—a modular prompting paradigm with guardrail hooks—to handle complex, multi-step tasks more reliably. Liguori emphasizes that traditional architectural principles remain critical when building agents at scale, recommending developers design, build, and test small modules (like agent tools) since comprehensive agent testing is inherently difficult.

### AWS Releases Loom, an Open-Source Reference Platform for Governing AI Agents at Enterprise Scale - (InfoQ)

https://www.infoq.com/news/2026/07/loom-aws-agent-platform/

# Summary

AWS has released Loom, an open-source reference platform designed to help enterprises build, deploy, and govern AI agents securely at scale on AWS. Built on the Strands Agents SDK and Amazon Bedrock AgentCore Runtime, Loom provides a unified management UI and backend API with built-in security controls including identity provider integration, role-based access controls, and lifecycle management for agents and resources. The platform addresses seven key challenges platform engineering teams face when scaling agent deployments, with particular emphasis on identity propagation—ensuring that when agents act on behalf of users through multiple service hops, the originating user's identity and permissions are preserved through the entire delegation chain.

Loom emphasizes governance through a configuration-driven deployment model that avoids runtime code generation, instead injecting behavioral guidelines and configurations into a pre-written agent. It implements governance through mandatory resource tagging, role-based and attribute-based access controls that determine what capabilities users can access, and human-in-the-loop review mechanisms for sensitive actions. AWS explicitly positions Loom as a reference architecture for how organizations might build their own agent platforms rather than as a managed service, allowing teams to customize and scan agent code once before reusing it across deployments.

### How Netflix Built GenPage: a Single GenAI Model to Build Personalized Homepages - (InfoQ)

https://www.infoq.com/news/2026/07/netflix-llm-homepage-generation/

# Summary

Netflix developed GenPage, a generative AI system that replaces its traditional multi-stage recommendation pipeline with a single unified model that directly generates personalized homepages. Rather than using separate components for candidate generation, ranking, and layout across multiple rows, GenPage uses a single generative model that answers one key question: "Given everything we know about this user and this request, what homepage should we generate to maximize user satisfaction?" The system employs post-training reinforcement learning to optimize across entire pages rather than individual rows, enabling whole-page customization.

In production, GenPage demonstrated significant improvements over the previous approach, including measurable increases in user engagement and a notable 20% reduction in end-to-end serving latency. A key finding was that enriching the prompt with better context proved far more impactful than scaling model capacity—context enrichment yielded a 6.9% improvement versus only 1.3% from scaling the model from 120M to 900M parameters. The system also unexpectedly increased homepage diversity and customization through its reinforcement learning post-training.

### Google's AlphaEvolve Reaches General Availability with Evolutionary Code Optimization as a Service - (InfoQ)

https://www.infoq.com/news/2026/07/alphaevolve-generally-available/

# Summary

Google announced the general availability of AlphaEvolve, an evolutionary code optimization service that uses AI agents to automatically improve code performance. The tool works by generating candidate program variations using Gemini models, scoring them against user-defined metrics, and iterating until finding optimized solutions. Notably, the deployment model keeps sensitive code secure by running evaluations client-side on the user's infrastructure while only the API generates candidates in the cloud, making it suitable for enterprises with proprietary code.

AlphaEvolve has demonstrated significant real-world impact across diverse use cases: Klarna doubled ML training throughput, JetBrains improved IDE latency by 15-20%, FM Logistics reduced warehouse routes by 10.4%, and Kinaxis increased forecasting accuracy by 22% while cutting runtime by 90%. However, the tool's effectiveness is limited to problems with clearly measurable, automatable evaluation functions—such as performance metrics, routing distances, or throughput—making it ideal for infrastructure and algorithmic optimization but less suitable for business logic where success criteria are ambiguous or subjective.

### How Uber Builds Zone-Failure-Resilient OpenSearch Clusters - (InfoQ)

https://www.infoq.com/news/2026/07/uber-opensearch-zone-failure/

# Summary

Uber has developed a zone-failure-resilient OpenSearch cluster architecture using isolation groups (IGs) and forced shard allocation awareness. The solution addresses the problem of uneven node distribution across physical zones, which previously caused clusters to enter yellow states with unassigned shards. By creating logical isolation groups with guaranteed equal node counts and mapping shards across these groups with multiple replicas, Uber ensures that a full zone failure plus one additional node failure can be tolerated while maintaining quorum and avoiding data loss.

The key innovation is preventing OpenSearch's default rebalancing behavior during zone outages, which would overload remaining infrastructure. Instead, Uber uses forced-awareness configuration to keep unassigned shards unallocated rather than triggering cascading reassignments. Combined with five cluster manager nodes (instead of three) and auto-shrinking voting configuration, this approach maintains cluster stability and data availability during failures. The solution leverages existing OpenSearch features and can be adopted by other organizations without requiring custom tooling or forked versions.

### Zero to Agent in 30 Minutes: Build a Workflow Agent with John Berryman - (Radar)

https://www.oreilly.com/radar/zero-to-agent-in-30-minutes-build-a-workflow-agent-with-john-berryman/

# Summary

This O'Reilly article discusses building AI workflow agents efficiently, featuring AI consultant John Berryman. He defines an agent as a large language model with two loops: an outer loop for user communication and an inner loop that lets the model choose and execute tools. Berryman emphasizes that while this dual-loop structure has remained unchanged since 2023, improvements in tools and natural language instructions now enable teams to build practical AI products around this simple pattern.

Berryman demonstrates a practical "outside in" approach to building AI products: start by building traditional software components (interface and data model), stub the AI with static responses to validate the system, then swap in a minimal agent with structured output requirements and a small toolkit (read, write, edit, shell access). Finally, encode the agent's intelligence as skills using plain English instructions rather than complex state machines, including checklists to verify task completion. This methodology allows subject matter experts to understand and directly update AI instructions without requiring intermediaries.

### The Tokens You Can’t Wait For - (Radar)

https://www.oreilly.com/radar/the-tokens-you-cant-wait-for/

# Summary

This article discusses the "GPU hangover"—the problem of underutilized AI hardware in enterprises that purchased private GPU clusters to maintain control over their AI systems. The core issue stems from a fundamental mismatch between how standard autoregressive language models (like GPT or Llama) generate text and how enterprises actually use them. These models generate one token at a time, creating a memory bandwidth bottleneck where GPUs sit idle waiting for weights to be loaded, unless they can batch multiple requests together. Large public APIs solve this through massive batching across thousands of users, but enterprise applications requiring sub-second response times (like real-time customer interactions) cannot batch effectively, leaving expensive hardware underutilized.

The article suggests that **text diffusion** is a promising solution to close this efficiency gap, as it could better match enterprise usage patterns. However, the authors caution that diffusion is also "the most oversold," and its actual benefits are limited to specific workload types, obscured by marketing hype. They emphasize that understanding which workloads truly benefit from diffusion is critical for enterprises to justify their hardware investments and improve GPU utilization rates.

### The Right Amount of Spec for Agentic Development - (Radar)

https://www.oreilly.com/radar/the-right-amount-of-spec-for-agentic-development/

# Summary

This O'Reilly article argues that while AI agents make code implementation cheaper and faster, the critical bottleneck has shifted to specification and verification rather than coding. The author challenges the notion that minimal specs are "lean"—instead, vague requirements simply defer costs to endless correction loops where humans must continuously review and clarify intent. The real trade-off is not between specification and no specification, but finding the optimal balance: enough structured detail to constrain the work, concrete examples to clarify intent, and executable checks so reviews don't become guesswork.

The article emphasizes that specification itself requires rigorous review, as even careful specs can contradict themselves, ignore edge cases, or describe behavior that cannot be verified. As implementation becomes cheaper through AI agents, the engineering challenge moves from producing code to deciding what "correct" means and reliably checking it—making specification quality and verification processes the true cost drivers rather than coding speed.
