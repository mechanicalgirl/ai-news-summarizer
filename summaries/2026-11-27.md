### Adapting CPython for yk - (Python Weekly)

https://tratt.net/laurie/blog/2026/adapting_cpython_for_yk.html

# Summary

Laurence Tratt describes his work adapting CPython for yk, a tool that automatically adds JIT compilers to C interpreters. After successfully applying yk to smaller interpreters like Lua, Tratt tested whether it would work with CPython, a much larger codebase. The result, ykcpython, not only works but achieves meaningful performance improvements—outperforming standard CPython on 12 of 13 benchmarks and Python's experimental JIT on 8 of 13 benchmarks, despite requiring only 3-4 days of direct work and about 450 lines of code additions.

Tratt emphasizes that ykcpython is not production-ready and uses this post to document his adaptation process. He explains how he started with minimal changes to CPython's tier 1 interpreter, encountered performance issues due to CPython's "quickening" optimization technique, and ultimately switched to CPython's tier 2 interpreter where yk support required only 80 lines of code. His approach demonstrates a practical methodology for adapting large interpreters to work with yk through incremental changes and careful measurement.

### Understanding Positional Embeddings in Modern LLMs - (Python Weekly)

https://magazine.sebastianraschka.com/p/understanding-positional-embeddings

# Summary

This article provides a comprehensive tutorial on positional embeddings in Large Language Models (LLMs), explaining how models encode and process token position information. It covers classic methods like learned absolute embeddings used in GPT-2, contemporary approaches like RoPE (Rotary Position Embedding), and how modern architectures handle positional information. The author uses visual examples, mathematical explanations, and PyTorch implementations to illustrate why explicit positional encoding is necessary—because while causal attention masks provide implicit order information, they don't distinguish between different distances between tokens.

The article begins by establishing why positional information is essential (e.g., word order changes meaning), then walks through different implementation methods. It examines how GPT-2 learns position vectors as a lookup table that are added to token embeddings before transformer blocks, contrasting this with newer models like MiniMax-M3 that integrate positional information directly within attention mechanisms. The piece serves as both a foundational reference for understanding LLM architectures and an answer to long-standing reader questions about how modern positional encoding methods like RoPE actually work.

### Faster CI with Orchestrated Pytest Workers - (Python Weekly)

https://making.close.com/posts/faster-ci-with-orchestrated-pytest-workers/

# Summary

Close's backend service runs nearly 58,000 integration tests in under 2.5 minutes using an orchestrated pytest worker approach. For 12 years, the company used deterministic test splitting across multiple CI runners with bin-packing optimization, but eventually hit performance limits around 12 minutes due to fixed-cost setup steps (container startup, test collection, etc.) that didn't scale with parallelization. Even with 17x parallelization, these overhead costs became the bottleneck.

To solve this, Close implemented a centralized orchestrator architecture inspired by currents.dev's Playwright testing approach. The orchestrator handles test collection and dynamic work distribution to multiple worker nodes, allowing fixed-cost setup steps to run in parallel with worker initialization. Workers only collect tests they need to run, dramatically reducing collection overhead. Combined with spot instance support (54 spot instances plus 2 on-demand runners), this approach achieved significant cost savings while maintaining fast CI speeds and enabling intelligent rebalancing when workers fail.

### How to find and fix N+1 queries in Django - (Python Weekly)

https://codewithstein.com/fix-n-plus-one-queries-django/

# Summary

**N+1 queries** are a common Django performance problem where a single database query triggers additional queries for related objects. For example, fetching 20 articles and then accessing each article's author, category, and tags results in 61 queries instead of one. The article explains how to identify these problems using Django Debug Toolbar and shows how to fix them: use **`select_related()`** for one-to-one and foreign key relationships (which uses SQL joins), and **`prefetch_related()`** for many-to-many and reverse foreign key relationships (which fetches related objects in separate batch queries). By applying these optimizations to the example, the query count drops from 61 to just 2 queries without changing the template code.

### Stricter checks for uploaded distributions on PyPI - (Python Weekly)

https://blog.pypi.org/posts/2026-11-18-stricter-checks-for-uploaded-sdists/

# Summary

PyPI has implemented stricter validation checks for uploaded Python packages to enhance security and prevent parser differential attacks—where subtle differences in how various tools interpret archive formats could allow malicious packages to appear legitimate. The new checks reject source distributions using legacy V7-style tar archives and built distributions containing problematic ZIP comments that could be misinterpreted as ZIP control structures.

For most users and package maintainers, these changes have minimal impact since the vast majority of packages already conform to proper standards. Maintainers who encounter upload rejections should ensure they're using modern Python build backends that automatically generate compliant distributions, or manually conform to requirements like using POSIX pax-style tar archives with UTF-8 filenames. PyPI plans to continue tightening these restrictions in the future, focusing on minimally disruptive changes that target obscure archive format features exploitable by attackers.

### Microsoft agent-framework Compromised Twice on PyPI - (Python Weekly)

https://safedep.io/blog/microsoft-agent-framework-pypi-compromise

# Summary

Microsoft's Python package `agent-framework` was compromised twice on PyPI on November 17, 2026, with malicious versions 1.26.1 and 1.26.2 stealing credentials and tokens from any environment that installs them. The malware uses a `.pth` file to run a stealer on Python startup without requiring the package to be imported, harvesting environment variables, credential files, tokens from Azure DevOps, Azure managed identity, and GitHub Actions, then exfiltrating the data. Additionally, a new maintainer account named "vibiret" created on the attack day was granted publishing access to agent-framework and five related packages, though it's unclear whether this account or the ESRP compromise was the primary attack vector. The last clean release is version 1.26.0.

### funkycache: a Python library to cache functions in SQLite - (Python Weekly)

https://alexwlchan.net/2026/funkycache/

# Summary

funkycache is a new Python library that simplifies function caching using SQLite, designed to speed up static site generation. Unlike basic key-value caching, funkycache uses a decorator pattern similar to `functools.cache`, automatically handling the complex logic of serialization, hashing, and cache invalidation. It stores arbitrary Python objects by converting function arguments to JSON, hashing them with XXH64 for efficiency, and serializing return values using Pydantic for type-safe retrieval.

The library intelligently manages cache invalidation by tracking dependencies on source files, template files, and static values like library versions. It also handles special cases like lazy generators by materializing them into lists with memory budgets. By encapsulating all caching logic in a single, well-tested library, developers can use `@cache.register` decorators without worrying about the underlying implementation details.

### zar-rs - (Python Weekly)

https://brmmm3.github.io/posts/2026/11/15/zar-rs/

# Summary

ZAR is a new archive format built in Rust with a Python API (pyzarlib) that offers significant speed and feature improvements over traditional formats like ZIP and tar.gz. It uses parallel Zstandard compression, achieves faster compression times (0.86 seconds vs. 11 seconds for ZIP on test data), and introduces features like commit-based versioning, content deduplication, and per-block checksums that allow users to maintain file history within a single archive and recover from corruption.

Beyond Python, the same Rust library powers command-line tools, desktop applications, and bindings for multiple languages (Go, Java, C#, WebAssembly, and others). ZAR is designed for users who need both quick archive operations and useful history management, making it suitable for backup systems, project snapshots, and version control rather than just one-off file compression.

### What makes uv slow? - (Python Weekly)

https://blog.schuetze.link/what-makes-uv-slow/

# Summary

This article explores the factors that make **uv** (a Python package manager) slow, despite its reputation for speed. The author explains that uv's performance comes from systematic optimization rather than shortcuts, following a hierarchy where the slowest operations—external tool invocation, network requests, CPU-heavy tasks, and disk I/O—are addressed first. The article provides detailed benchmarks across different scenarios (Jupyter, Airflow, Boto3, Home Assistant, and Plotly) on various hardware configurations, showing concrete performance metrics like cold-cache installation times and overhead measurements.

The article identifies specific bottlenecks including TOML file parsing (which is inherently slow in Rust), metadata prefetching strategies, missing wheel availability, complex version representation, and dependency resolution backtracking. Additional slowdown sources include virtual environment setup, compression/decompression, network reliability, interpreter discovery, and memory allocation patterns. The author emphasizes that most optimizations focus on eliminating high-level inefficiencies (like avoiding repeated builds by using wheels) before addressing lower-level concerns like memory management, acknowledging that some slowdowns are unavoidable costs of maintaining correctness and flexibility in a complex system.

### Abolish Lock Poisoning - (Armin Ronacher's Thoughts and Writings)

https://lucumr.pocoo.org/2026/11/25/poisoning/

# Summary

Armin Ronacher argues that Rust's mutex poisoning feature—which prevents further lock access after a panic occurs while holding a mutex—should be removed or made optional. He contends that poisoning is ineffective in practice, citing evidence that no one in the wild actually recovers from poisoned locks correctly. Instead, the most common response is `lock().unwrap()`, which converts the poison error into another panic, potentially causing cascading failures across an entire application rather than failing fast.

Ronacher highlights several concrete problems: the PoisonError holds the lock guard, creating deadlock hazards in error handling code; poisoning causes single panics to propagate into outages affecting all future lock access; and even Rust's own standard library ignores poisoning in its internal mutexes. He also notes the inconsistency of only applying poisoning to Mutex but not RefCell, despite similar invariant-breaking scenarios occurring in both. His proposal is to make non-poisoning locks the default, with an optional `Poison<T>` wrapper for those who genuinely need the feature.
